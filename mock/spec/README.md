## 2. Детерминизм, временна́я привязка и целевые объёмы

- **Детерминированный генератор:** `--seed 20261126` (по умолчанию). Все случайные потоки разделяются по подсистемам (`seed + 1` каталог, `seed + 2` клиенты, `seed + 3` журнал, `seed + 4` Метрика), чтобы правка шаблонов журнала не меняла артикулы каталога и профили клиентов.
- **Якорь дат (`--today`):** по умолчанию текущая дата запуска `build-mock` (UTC+3 / Europe/Moscow). Все смещения `expires_in_days`, `purchased_days_ago`, `days_ago` (`SPEC.md` §24.6) и окно 90 дней (`D-89 .. D-0`) вычисляются от `--today`, чтобы на демо 26 ноября (или в любой другой день) истекающие лицензии и 30-дневные тренды оставались актуальными.
- **Целевые объёмы артефактов (`var/data/`):**

| Артефакт | Путь | Целевой объём |
|---|---|---|
| Каталог предложений | `var/data/mock_catalog.json` | 15 000 – 25 000 SKU (offers) ≈ 400 – 650 карточек (семейство × редакция), по `kb/families/*.yaml` и `SPEC.md` §19 |
| База клиентов | `var/data/mock_clients.json` | **311 клиентов** (11 демо-профилей из `profiles.yaml` + 300 синтетических из `clients.yaml`) |
| Журнал и события | `var/data/kuznitsa.sqlite` (`searches`, `events`) | **45 000 поисков** (`source='history'`, `engine='legacy'`), **~24 000 сессий**, **~165 000 событий** (`impression`, `click`, `cart`, `order`, `lead`, `exit`, `reformulate`, `suggest_*`) |
| Выгрузки Метрики | `var/data/mock_metrika/` | `metrika_search_phrases.csv` (~3 500–5 000 агрегированных фраз), `metrika_visits.jsonl` (~24 000 визитов), `metrika_hits.jsonl` (~110 000 хитов) |

## 3. Порядок генерации (`cli build-mock`)

1. **Каталог (`catalog`):** загрузить `kb/` → развернуть семейства с `catalog: yes` в SKU и карточки (`SPEC.md` §19). Сохранить намеренные **контентные дефекты** для находок `INS-07`, `INS-08`, `INS-09` (помечать в метаданных генератора, не ломая остальные 95% карточек):
   - у 14 конкретных карточек из `backup_recovery` / `ngfw_vpn` оставить пустым тег `astra`/`redos` в `platforms` (`INS-07`);
   - у 9 карточек из `office_suite` / `cad_2d` оставить `registry_ru = null` / `vat = 22` (`INS-08`);
   - у 11 карточек из `endpoint_security` пропустить диапазоны `25–49` и `50–99` или `max_seats` (`INS-09`);
   - продукты `Cursor IDE`, `Яндекс Трекер`, `Obsidian` оставить **вне каталога** (`catalog: no` или не генерировать SKU), но присутствующими в KB/словаре для `INS-04`..`INS-06`.
2. **Клиенты (`clients`):** загрузить 11 демо-профилей из `profiles.yaml` + сгенерировать 300 синтетических клиентов по `clients.yaml`, привязав `owned` и `orders` к реальным `card_id`/`offer_id` сгенерированного каталога (с сохранением исходных названий).
3. **Журнал (`querylog`):** прогнать сгенерированные запросы через `naive` (в режиме `engine='legacy'`), промоделировать поведение пользователя (`click`/`cart`/`order`/`lead`/`reformulate`/`exit`), затем подмешать 18 посеянных аномалий (`querylog.yaml` §7) и записать в `kuznitsa.sqlite`.
4. **Метрика (`metrika`):** конвертировать ровно те же сессии и события из шага 3 в 3 файла `var/data/mock_metrika/` по спецификации `metrika.md`. Это гарантирует 100% сходимость цифр между SQLite и адаптером импорта Метрики.
5. **Предрасчёт инсайтов (`insights`):** прогнать `insights.py` и убедиться, что все 18 находок (`INS-01`..`INS-18` из `design/proposals/neon2/analytics.md`) сформированы в статусе `new`.

## 4. Чек-лист валидации после `build-mock`

После сборки генератор (или `pytest`) проверяет инварианты:
- Все 11 `demo: true` профилей присутствуют с точными `id`, у 10 не-гостевых профилей есть минимум 1 лицензия с `expires_in_days` в диапазоне `10..60`.
- Суммарно в когорте истекающих (`14 <= expires_in_days <= 45`) находится `30..38` клиентов (цель `34` под `INS-17`).
- Доля нулевой выдачи в `legacy`-журнале лежит в диапазоне `21%..28%` (цель `~24.8%`), доля шума (`hardware|piracy|off_topic|gibberish`) — `2.5%..3.5%`.
- В 15–25 числах каждого месяца суточный объём запросов по категории `accounting_1c` выше базового минимум в `1.35×`.
- Все 18 эталонных находок `INS-01`..`INS-18` воспроизводятся с объёмом в пределах ±15% от ориентиров `design/proposals/neon2/analytics.md`.
- Суммарная выручка и число заказов в `metrika_visits.jsonl` совпадают с `events WHERE type='order'` в SQLite с точностью до 100%.

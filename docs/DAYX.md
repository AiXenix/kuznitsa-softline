# 26 ноября · от файлов до показа

Ведущий выполняет блоки Bash по порядку в одном терминале из корня копии проекта. Положите файлы выдачи в `var/incoming-26/` или задайте `SOURCE` равным пути к полученной папке. Для репетиции E1 перед первым блоком выполните `export SOURCE=/home/bb/kuznitsa-softline-ops/rehearsal/set1/organizer`. Копируйте только полученный каталог, историю и аналитику. Снимок и исходные файлы будут лежать в разных папках внутри `var/`.

## 1. Принять файлы и собрать снимок

На 26 ноября при доступном шлюзе рекомендуем `jev`: на E1 он дал 96,57% покрытия классов за $0.037; полный `day` занял 301,2 с. Для этого выполните `AI=jev` в том же терминале перед первым блоком. Для показа без сети или при ограниченном времени оставьте `embed` (значение по умолчанию): 88,53% классов, $0 и 268,0 с. Время относится к 7 003 предложениям и полному повтору истории E1 на этой машине. Проверочные команды ниже выполняются дополнительно. Лимит $0,20 относится к раскладке данного снимка. При отказе шлюза оставшиеся вопросы обрабатываются локально. Для каждого запуска создаётся новый каталог. Подтвердите курс у организаторов, если прайс в долларах. По умолчанию для репетиции принят курс 100 ₽/$.

```bash
set -eu
export HF_HUB_OFFLINE=1 OPENBLAS_NUM_THREADS=1 KZ_LLM=off
PY=/home/bb/kuznitsa-softline/.venv/bin/python
SOURCE=${SOURCE:-"$PWD/var/incoming-26"}
test -d "$SOURCE" || { printf 'Положите файлы в %s\n' "$SOURCE"; exit 1; }
AI=${AI:-embed}
BUDGET=${BUDGET:-0.20}
export KZ_USD_RUB=${KZ_USD_RUB:-100}
RUN=$(mktemp -d "$PWD/var/dayx-XXXXXXXX")
INPUT="$RUN/incoming"
SNAP="$RUN/snapshot"
mkdir "$INPUT"
cp -pR "$SOURCE/." "$INPUT/"
"$PY" -m kuznitsa.ingest.cli day "$INPUT" --out "$SNAP" --ai "$AI" --ai-budget-usd "$BUDGET"
cat "$SNAP/day_report.md"
```

Сверьте строки каждого прайса, таблицы остатков и истории с объёмом выдачи. У фида принятыми считаются и строки, присоединённые к основному прайсу. Для уникальных предложений смотрите число в разделе покрытия. Убедитесь, что в отчёте отдельно подписаны поиск по сайту и фразы из поисковиков. Внешние визиты учитываются в привлечении. В разделе самопроверки посмотрите топ-3 и топ-5 для артикула, названия и класса с вендором. Покрытие показывает долю привязок к основной базе знаний. Для проверки правильности откройте примеры решений в `import_ai.jsonl` и строки с пропусками в `import_report.json`.

Если прайс пропущен, откройте в `day_report.json` запись файла, поля `reason`, `best_guess` и `columns`. Для табличного прайса с нестандартными заголовками укажите справа точные названия колонок. Следующий блок нужен **только для исправления соответствия**. Для журнала с неузнаваемой шапкой запросите колонку «Запрос» и фактические «Частота» или «Результаты». Для Метрики сохраните название исходного отчёта и колонки Метрики. Карта ниже относится к каталогу. При неподдерживаемом формате запросите выгрузку в XLSX, CSV, YML, JSON или CommerceML.

```bash
cat > "$RUN/map.yaml" <<'MAP'
name: Полный заголовок позиции
source_id: Номер строки номенклатуры
vendor: Компания-разработчик
category_path: Раздел магазина
price: Отпускная сумма
MAP
SNAP="$RUN/snapshot-corrected"
"$PY" -m kuznitsa.ingest.cli day "$INPUT" --out "$SNAP" --mapping "$RUN/map.yaml" --ai embed
cat "$SNAP/day_report.md"
```

### Если в каталоге есть снятые позиции

В `day_report.md` сверяйте строку «Снято с продажи» с фильтром активности в админке магазина. Откройте `inactive_offers.jsonl` в папке снимка: у записи есть исходные коды, колонка и значение, по которым позиция снята, а также `attrs.active=false` и `attrs.sold=false`. Поисковый индекс и КП используют только действующий каталог. Нулевой остаток сам по себе означает отсутствие на складе. Если снято неожиданно много, сверьте в выгрузке смысл колонок «Активность», «Снят с продажи» и «Статус», затем повторите импорт в новый снимок.

Для выгрузки админки распознаются `PROPERTY_ARTNUMBER`, `PROPERTY_SERIES`, `PROPERTY_VENDOR`, `PROPERTY_MANUFACTURER`, теги из `PROPERTY_SEARCH_TAG` и `TAGS`. Разделы могут быть записаны через `/` или `>`. В описании остаётся текст HTML. С агрегированными целями Метрики после подключения соответствующего распознавателя B в отчёте появится строка «Метрика · достижение целей».

### Если передали номенклатуру и цены из 1С:УТ

Положите обе книги в папку выдачи перед запуском `day`. В «Номенклатуре» импорт читает уровни группировки строк Excel, отступы названий или колонку «Родитель». Сверьте путь двух товаров из соседних подразделов. В таблице файлов найдите «Таблица цен» и проверьте число присоединённых строк. Для соединения нужен общий код или артикул. «Розничная» заполняет основную цену предложения. Оптовые и специальные цены лежат в `attrs.prices` в рублях под исходными названиями. При пустой розничной цене основная цена остаётся «по запросу».

Чтобы назначить цену госзаказчику, согласуйте название с владельцем прайса и сохраните соответствие у снимка. Команда проверяет, что хотя бы у одной позиции есть такой вид цены, и печатает пример для сверки. Сегмент профиля госзаказчика в движке — `gov`.

```bash
"$PY" - "$SNAP" gov 'Для госзаказчиков' <<'PYTHON'
import json, sys
from pathlib import Path

snapshot, segment, label = Path(sys.argv[1]), sys.argv[2], sys.argv[3]
with (snapshot / "catalog.jsonl").open() as catalog:
    for line in catalog:
        offer = json.loads(line)
        prices = offer.get("attrs", {}).get("prices", {})
        if label in prices:
            print(offer["name"], "· розничная", offer.get("price"), "·", label, prices[label])
            break
    else:
        raise SystemExit(f"В снимке нет вида цены «{label}». Проверьте название колонки.")
file = snapshot / "segment_price_types.json"
policy = json.loads(file.read_text()) if file.exists() else {}
policy[segment] = label
file.write_text(json.dumps(policy, ensure_ascii=False, indent=2) + "\n")
PYTHON
```

Передайте ведущему этот файл вместе со снимком. Выбор цены по профилю в выдаче и КП подключает поток A. Для проверки на витрине используйте код напечатанного предложения и профиль госзаказчика.

Страницы одного отчёта API Метрики и CSV обращений покупателей кладите отдельными файлами в ту же входную папку. В совместной версии с B6 у каждой страницы в отчёте дня появится роль «Метрика · API отчётов», у CSV — «Обращения в чат поддержки». Сверяйте принятые строки страниц с числом записей в `data`, а обращения — с числом записей чата. Если чат пропущен, сверьте заголовки с формой, которую распознаёт B6: «Дата», «Покупатель», «Сообщение клиента». Для покупателя подойдёт обезличенный идентификатор.

### Если передали JSON МойСклад

Сложите в одну входную папку все сохранённые страницы ассортимента или товаров, модификаций, групп и остатков. У МойСклад страницы с разными `meta.offset` могут иметь одинаковый заголовок. Сохраните их в разных файлах. Команда `day` связывает записи по UUID. В `day_report.json` у каждого файла есть объект `page` с количеством полученных строк и переданными API значениями `offset` и `size`. По ним можно проверить полноту выгрузки.

Для сверки возьмите артикул модификации. Проверьте путь группы, редакцию и собственную цену модификации в рублях. При наличии `quantity` доступность берётся из свободного количества, иначе — из `stock`. В таблице файлов пропуск строки остатков означает, в частности, что соответствующая позиция отсутствует в выданном каталоге. Для названий единиц и стран при передаче данных только ссылками запросите выгрузку с раскрытыми `uom` и `country`. [Образец страниц](ingest_examples/day_moysklad)

## 2. Проверить поиск на новом снимке

Команды ниже адресованы только созданному снимку. Для первой проверки команда берёт исходный код из файла предложений, а при его отсутствии — название. Сверьте код в первой карточке. Затем посмотрите выдачу по смыслу и примеры промахов в разделе `worst` файла самопроверки.

```bash
export KZ_DATA_DIR="$SNAP" KZ_CACHE_DIR="$SNAP/cache"
CODE=$("$PY" -c 'import json,sys; rows=map(json.loads,open(sys.argv[1])); first=next(rows); print(first.get("source_id") or next((x["source_id"] for x in rows if x.get("source_id")),first["name"]))' "$SNAP/catalog.jsonl")
"$PY" -m kuznitsa.cli search "$CODE" --mode fast > "$RUN/search-code.json"
"$PY" -m kuznitsa.cli search 'антивирус на 30 пк' --mode fast > "$RUN/search-class.json"
"$PY" -m kuznitsa.ingest.cli selfcheck --mode fast --seed 7 --n 300 --report "$RUN/selfcheck.json" > /dev/null
"$PY" -c 'import json,sys; print(json.load(open(sys.argv[1]))["overall"])' "$RUN/selfcheck.json"
"$PY" - "$RUN/search-code.json" "$RUN/search-class.json" <<'PYTHON'
import json, sys
from kuznitsa.analytics.store import result_cards
for path in sys.argv[1:]:
    cards = result_cards(json.load(open(path)))
    print(path, [(c["title"], c["offer"].get("source_id")) for c in cards[:3] if c.get("offer")])
PYTHON
```

## 3. Показать бизнес-итоги

```bash
"$PY" -m kuznitsa.cli kpi > "$RUN/kpi.json"
"$PY" -m kuznitsa.cli digest > "$RUN/digest.json"
"$PY" - "$SNAP/day_report.json" <<'PYTHON'
import json, sys
r = json.load(open(sys.argv[1]))
replay = r["replay"]
n = replay.get("frequency", 0)
if n:
    print("Поисков с учётом частоты", n)
    print("Без результата до / после", *(f"{replay[k]/n:.1%}" for k in ("before_zero", "after_zero")))
    print("Восстановлено", replay["recovered"])
for item in r["agent"]["items"]:
    print(item["title"])
PYTHON
```

Покажите частоту исторических фраз, долю пустых ответов до и после повтора и примеры восстановленных запросов. Оценка в рублях — прогноз на исторических данных. Фактические заказы и заявки сверяйте с KPI и CRM. Покажите первую рекомендацию агента и пример запроса, на котором она основана. Если историю не передали, покажите покрытие и самопроверку, а бизнес-показатели оставьте без оценки.

## 4. Передать ведущему переключение и возврат

До переключения ведущий сохраняет из действующей конфигурации стенда пути к каталогу и кэшу действующего демо. Отдельно фиксирует пути к каталогу и кэшу нового снимка. Команда печатает пути для ведущего.

```bash
printf 'KZ_DATA_DIR=%s\nKZ_CACHE_DIR=%s\n' "$SNAP" "$SNAP/cache"
```

Ведущий подставляет эту пару в конфигурацию стенда и переоткрывает движок своей командой. Сверьте число карточек с `day_report.json`, найдите тот же исходный код на витрине и проверьте показ KPI в консоли. Для возврата ведущий восстанавливает сохранённую пару путей демо и переоткрывает движок. Контроль возврата — поиск демо-артикула `FQC-10572`. Исходный каталог, его журнал и оба снимка сохраняются до конца показа.

## Поисковый ответ

Все текстовые поля API выводятся через DOM как текст. Каждый блок использует `type` и необязательный `title`. Пустое значение скрывает соответствующую часть. Ноль в стоимости, времени и количестве сохраняется.

| Тип | Поля и действия |
|---|---|
| `products` | `total`, `items[]` с карточками. Страницы переключаются через `page`. |
| `kit` | `role, seats, total, slots[].{title,must,note,card,alternatives}`. Цена комплекта от движка. |
| `analogs` | `source.{title,note}, items[].{note,card}`. |
| `answer` | `title, text, source, links[]`. У ссылки читаются `label/title/text` и `q`. Переход запускает поиск по `q` или подписи. |
| `spec` | `lines[].{n,raw,understood,status,card,qty,unit_price,total,alternatives}, total, unresolved`. Статусы `matched, ambiguous, not_found`; итог приходит готовым. |
| `compare` | `columns[].title, rows[].{title,values}`. Значения соответствуют порядку колонок. Таблица прокручивается внутри блока. |
| `not_in_catalog` | `title,text,reason`. При отсутствии текста видна причина. |
| `categories`, `vendors` | `items[].{title,count}`. Выбор запускает поиск по названию. |
| `my_licenses` | `items[].{title,qty,expires_in_days,renew_offer}`. Для предложения продления видны название, артикул и цена. |
| `clarify` | `question, options[].{label,apply}`. Поддержаны новый запрос и дополнение фильтров. |
| `services` | `text, items[]` с карточками услуг или `{card,note}`. |
| `promo` | `text, items[]` с `title,text` или карточкой предложения. |
| `lead` | `title,text,action`. Кнопка для `request_quote` записывает событие `lead`. |
| `crosssell` | `title, items[].{card,reason}`. События несут `payload.block = crosssell`. |

Карточка читает `card_id,position,title,vendor.name,category.title,summary,badges[].label,offer,calc,price_from,variants,variants_count,score`. У предложения читаются `offer_id,name,sku,price,price_on_request,available`. У расчёта приоритет имеет `calc.text`, затем полное выражение по `qty,unit_price,total` или цена «от». Единицу и период в фразе «за устройство в год» поставляет движок. UI не подставляет минимальный тираж. «Почему здесь» раскрывает `score.tier,score.parts.{rel,pop,margin,pers},score.why[]`. Полный список вариантов по запросу загружается из `/api/card/{id}`.

Над выдачей используются `understood.intent_title, chips[].{key,label,removable}, inherited.from_q`, а также `query.corrected,corrections,did_you_mean`, `banners[].text, notes[], facets[].{key,title,values}, relax_hints[].{label,count,drop,apply}, related_queries[]`. Снятые условия накапливаются в `ignore`. Исправление отклоняется через `verbatim`, цепочка сбрасывается через `context: off`. Новый текст запроса сбрасывает ручные фильтры. Ввод спецификации сохраняет переносы строк в `q`.

Трасса выводит фактический массив `trace[].{step,title,status,ms,summary,detail}`, `timing_ms.total`, `cost.llm_calls,cached,rub,saved_rub`. Подробности раскрываются с клавиатуры. Идентификатор `search_id` ведёт в инспектор.

## Состояние и события

Основная сессия живёт во вкладке. Смена профиля начинает отдельную сессию. Галерея передаёт `source: gallery`, независимые колонки сравнения используют собственные сессии и `source: compare`. В сравнении профилей позиции сопоставляются с первым столбцом по card_id. В сравнении режимов обе колонки ссылаются на позицию в соседнем показанном списке. Для профилей можно выбрать двух или трёх клиентов. Корзина живёт до перезагрузки страницы. Каждая позиция хранит исходный поиск и профиль для последующего события заказа.

Раскрытие лицензии и «Почему здесь» отправляют `click`. Добавление и завершение заказа отправляют `cart` и `order`. При новом запросе и на `pagehide` уход с основного результата без взаимодействия отправляет `exit` через `fetch` с `keepalive`. При ошибке оформления подтверждённые позиции уже убраны из корзины, оставшиеся можно оформить повторно. Ссылки в галерее, инспектор и образцы не создают торговые события.

## Допущения к разделу 17

- `services` и `promo` используют общий список `items`. Вложенная карточка допустима также в `alternatives`. Текстовые альтернативы ожидаются в виде объектов с `title`.
- `spec.unresolved` допускает число или список позиций. Пояснение строки может быть строкой или объектом с подписью.
- Инспектор принимает ответ поиска непосредственно, под `response/result` либо строку журнала под `search`. Для архивной строки распознаются `archived_summary,trace,ms,llm_calls,cost_rub`. Стоимость берётся из `items[].rub_per_query`, качество из `scenarios[].passed/total`. Для последнего прогона поддержаны строки `{scenario,status}` из `/api/admin/eval` в массиве, `rows` или `results`. Метаданные сценария могут содержать `eval_status/status`. В галерее статус показывается только при наличии данных. На странице решения отсутствующие показатели имеют атрибут `data-pending`.
- Примеры на странице образцов читаются только из `web/fixtures`. `products.json` сохранён из TestClient с текущим каталогом; остальные примеры иллюстрируют контракт. Рабочие страницы получают данные только из API.

## Добавление типа блока

Добавьте название и обработчик в `web/js/blocks.js`. Сохраните минимальный ответ с массивом `blocks` в `web/fixtures/<type>.json`, внесите имя в `index.json`, поля в таблицу выше и в проверку `tests/web/test_storefront.py`. Откройте `/styleguide` для проверки узкого экрана и навигации с клавиатуры. Статика отдаётся без сборки с ETag и повторной проверкой кэша, страницы — с `Cache-Control: no-store`.

## Управление показом

Поиск сохраняет в адресе `q,profile,mode,category`. Сравнение добавляет `compare=modes|profiles`, выбор колонок сохраняется в `profiles`. Параметр `criteria` переносит фильтры, снятые условия, страницу и настройки исправления/наследования. Переходы назад и вперёд восстанавливают запрос и получают актуальный ответ. Клавиша / переводит фокус в поиск, Esc закрывает подсказки, диалог или развёрнутую трассу.

Вход в регламент через кнопку в подвале или `/?show=1`. Переключатель выбирает короткий или расширенный маршрут из `web/demo/steps.json`. Кнопки панели, клавиши ←/→ и Alt+←/→ открывают очередную ссылку. Шаг хранится в адресе и в sessionStorage. Открытие вкладок аналитики во время регламента само по себе не меняет правила магазина.

Карточка выводит выбранное предложение, таблицу вариантов по структурным полям лицензии, вклад факторов и веса из шага трассы. У составного расчёта читаются `calc.items[].{count,pack,price}`, исходное выражение берётся из `calc.text`. Цвет монограммы вычисляется по названию вендора.

Показ выдачи пишет `impression`, выбор подсказки — `suggest_click` с идентификатором запущенного поиска. Название, варианты и объяснение пишут `click` с `payload.action=card|variants|why`. Переход по похожему запросу пишет `reformulate` с `payload.block=related` на исходном поиске. Для запроса цены используется `lead`.

## Консоль бизнеса

Вкладки работают в одной странице. Hash содержит выбранную роль, фильтры и адрес карточки. Данные читаются из `/api/admin`. Для открытого демо на сервере включается `KZ_ADMIN_OPEN=1`. Ключ из поля в шапке сохраняется в sessionStorage этой вкладки браузера и передаётся в заголовке X-Admin-Token. На запросы с записью и на POST /preview распространяется та же серверная проверка ключа. Консоль показывает отдельные состояния загрузки и ошибок каждого отчёта.

| Адрес | Что открывается |
|---|---|
| `/admin#head` | Сравнение парного прогона, потери, плитки, временной ряд, веса, стоимость и качество. `section=weights` и `section=cost` ведут к соответствующим блокам, `daily` задаёт нагрузку, `q` — фразу предпросмотра. |
| `/admin#ecom?kind=low_ctr` | Воронка наблюдаемого поведения, запросы, причины неудач, предложения менеджеру и правила. Допустимы также reformulated и zero. |
| `/admin#product` | Популярные и растущие запросы, сортируемые срезы, спрос на ушедшие продукты и события по заменам. |
| `/admin#content` | Пробелы и оценки потерь из API, разрезы, дефекты карточек и предложения для контента. |
| `/admin#agent` | Фильтры role, type, status и sort=asc. По умолчанию первыми идут находки с наибольшей ожидаемой оценкой. `id` открывает одну карточку. |
| `/admin#agent?type=add_synonym&status=new&first=1` | Шаг показа разрешается в реальный ID предложения по текущему ответу API. Применение, проверка и отклонение происходят по нажатию соответствующей кнопки. |
| `/admin#log` | Последние поиски при поддержке kind=recent&limit=50. Для B1 после 422/404 показана таблица популярных фраз с пояснением. |

Доли totals и slices представлены в API дробями, проценты tiles уже масштабированы сервером. Воронка B1 восстанавливает число поисков с событием из behavioral_searches и соответствующей доли. Для сравнения пустой выдачи знаменатель — frequency, для попадания в пятёрку — labeled. В случае B2 массив pairs заменяет локальное построение этих двух пар. Для unit=rate/ratio/fraction ожидаются дроби, для %/percent/pct — проценты. Потери и финансовая оценка восстановленных поисков выводятся из lost_orders и replay. Складывать эффекты предложений нельзя из-за пересечения сессий.

Смена веса одного фактора пропорционально распределяет остаток между другими факторами. Если их сумма равна нулю, остаток делится поровну. Предпросмотр использует копию весов и исходную фразу. Кнопка сохранения записывает веса через API. Таблица проверки предложения строится по verification.before/after. Для обеих сторон используются n_cards и search_id. В B1 при отсутствии n_cards подпись указывает длину сохранённого списка.

Для ссылки без search_id обработчик `GET /api/admin/ui/search-reference?q=…` в pages.py применяет ту же авторизацию, что и консоль, и находит последнюю запись по точному q_raw. Время записи и search_id определяют порядок. Если сервер не находит строку, инспектор показывает 404 и ссылку на поиск. Для строк с идентификатором используется непосредственный адрес `/inspect/{search_id}`. Архивная сводка позволяет запустить новый поиск. У полной записи трасса раскрыта слева, сохранённые карточки находятся справа.

Компоненты консоли лежат в web/js/admin. Общие функции отвечают за запросы, числа, ошибки, таблицы и ссылки. Визуализации используют встроенный SVG. Тесты проверяют маршруты FastAPI, доступ к переходу по фразе и отрисовку вкладок в Chrome на образцах B1, разреженных данных и дополнительных полях B2.

Шаг может показывать собственную цену `detail.calls[].rub`. В инспекторе видны непустые данные шагов, исходный JSON доступен по раскрытию. |
| Деньги | Форматирование использует русскую локаль и неразрывные пробелы. Сумма меньше рубля округляется до двух значащих цифр. Для цены одного поиска рядом показан эквивалент за тысячу запросов. |
| Показ и справка | Под панель ведущего выделяется место вне прокручиваемой области. На шагах экономики и весов соответствующий блок выносится в начало вкладки. На странице решения у каждого вида поиска есть ссылка с запросом и профилем из галереи. |

## Данные консоли в C3

Запросы вкладки запускаются при её открытии. Секции рисуются независимо. Одновременные обращения к одному адресу используют общий Promise. Успешный GET остаётся в памяти страницы до обновления, изменения ключа или успешной записи. Долгое ожидание и ошибки дают возможность повторить загрузку отдельной секции.

- У пар из `kpi.pairs` используются единица, направление улучшения, размеры обеих выборок и примечание. `kpi.funnel[].count` задаёт абсолютные значения этапов.
- `GET /api/admin/ui/history-days` читает журнал с той же авторизацией, что консоль. Поле `period` содержит крайние московские даты журнала. Для ряда `items` запрос выбирает только источник `history`. Последний отрезок графика рисуется пунктиром.
- Экономика использует `sent, cached, cache_rate` и `items[].rub_per_query, rub_per_1000, rub_per_100000, monthly_rub`. Для оценки на 100 000 умных поисков предпочтителен итог по режиму smart. Если даны две группы умного режима, их стоимость взвешивается по числу запросов. Общий месячный прогноз относится ко всем режимам.
- В журнале поддерживается `queries?kind=recent&limit=50`. Автообновление перечитывает только эту таблицу через пять секунд после предыдущей загрузки. В консоли B1 ответ 422 или 404 переключает блок на популярные фразы. Примеры запросов с собственным `search_id` ведут прямо в соответствующую запись.
- На вкладках контента и журнала `ingest.catalog` читается в форме §26.5. Показываются `ts, files, rows, offers, rejected, duplicates, recognized, auto, issues[].examples, unmatched`. При отсутствии отчёта приводится команда импорта.

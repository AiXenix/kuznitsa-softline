# Каталог организаторов → поиск

Из корня копии один раз задайте переменные оболочки. Отдельная папка данных позволяет проверить каталог, не затрагивая демо и его историю.

```bash
export HF_HUB_OFFLINE=1 KZ_DATA_DIR="$PWD/var/catalog-organizers" KZ_CACHE_DIR="$PWD/var/cache-organizers"
PY=/home/bb/kuznitsa-softline/.venv/bin/python
```

Три команды для стенда. Замените путь к примеру на файл организаторов. Справочник категорий можно передать вторым путём в той же команде.

```bash
"$PY" -m kuznitsa.ingest.cli import-catalog docs/ingest_examples/price.xlsx
"$PY" -m kuznitsa.cli build-index
"$PY" -m kuznitsa.cli search 'антивирус на 30 пк' --mode fast
```

Импорт также доступен через `-m kuznitsa.cli import-catalog`. Для показа витрина должна открыть тот же `KZ_DATA_DIR`. Работающий экземпляр движка читает снимок при запуске.

## Входные файлы и пробный прогон

CSV/TSV читаются в UTF-8 (включая BOM) и Windows-1251. XLSX читается по листам, шапка ищется среди первых 50 строк, значения объединённых ячеек распространяются в пределах объединения. У ячеек с формулами используется сохранённый результат Excel. JSON может содержать массив товаров внутри объекта. JSONL содержит один объект на строку. Расширение YML означает XML-фид Яндекс Маркета, включая категории, атрибуты offer и элементы param. Цены указываются в рублях. Для отдельных справочников используйте `id, parentId, title` и ссылку `categoryId` у товара.

Для диагностики добавьте `--dry-run --report preview.json` к первой команде. Она выведет результат и запишет только запрошенный отчёт. При обычном запуске в папке данных появляются `catalog.jsonl`, `kb_auto.yaml` и `import_report.json`. Артикул определяет стабильный идентификатор. У повторов сохраняется первая пригодная запись. При пустом или полностью нечитаемом входе CLI сообщает об ошибке и сохраняет предыдущий снимок. Если все позиции полного прайса явно сняты с продажи, их архив публикуется с пустым поисковым каталогом, и CLI сообщает об отсутствии предложений для показа.

## Что посмотреть в отчёте

- `rows = offers + duplicates + rejected`. По каждому листу и файлу в `sources` указаны принятые заголовки и список `unused`. Общий `columns` показывает первое встреченное соответствие.
- `recognized` показывает заполнение среди принятых предложений. Для вендора, семейства и категории учитываются попадания в основную БЗ. Для лицензии достаточно одного установленного поля. Точность разбора измеряется отдельно сравнением с размеченным эталоном в тестах.
- `examples[].fields` у первых предложений содержит значение, уверенность, источник и исходный фрагмент. Явное поле имеет приоритет перед характеристикой товара, затем идут правила названия и БЗ.
- `issues` содержит число случаев и до пяти примеров с файлом и строкой. Проверяйте строки без цены, битые записи, повторные артикулы, пропуски описания и категории. Ценовой выброс обозначает десятикратное отличие от медианы при трёх и более ценах в семействе. Сначала проверьте, не сравниваются ли разные пакеты или сроки.
- `unmatched` и `auto` показывают неизвестные семейства и производителей. Проверьте группировку в `kb_auto.yaml`. Уточнить неоднозначное название можно отдельными полями `family_name`, `edition`, `vendor`, а категорию — полным путём. Затем повторите импорт и сборку индекса.
- `notes` подсказывает, какие сигналы отсутствуют. Нейтральные популярность и маржа равны 0,5. История заказов загружается отдельно. Если источник знает только остаток, он помогает оценить доступность и служит приближением популярности.

## Как исправить заголовки

Передайте `--mapping map.yaml`. Слева пишется канонический ключ, справа — точный заголовок поставщика. Сопоставление действует во всех входных файлах с этим заголовком.

```yaml
name: Полное имя позиции
sku: Код поставщика
price: Для конечного клиента
vendor: Торговая марка
category_path: Путь в классификаторе
term_months: Длительность договора
```

Для незнакомой линейки без артикула идентификатор вычисляется из данных строки. Исправление текста такой позиции может изменить идентификатор. Явный артикул позволяет сопоставлять её между выгрузками.

## День данных одной командой

Положите файлы организаторов в отдельную папку. Команда обходит вложенные папки, определяет назначение таблиц по заголовкам и значениям, импортирует предложения, строит поисковый индекс, загружает историю и Метрику, повторяет исторические запросы, собирает предложения агента и запускает самопроверку. Для повторной репетиции задайте новое имя выходной папки. Без `--out` команда создаст папку `day-*` рядом с действующей и напечатает путь к отчёту.

```bash
export HF_HUB_OFFLINE=1 KZ_USD_RUB=100
PY=/home/bb/kuznitsa-softline/.venv/bin/python
"$PY" -m kuznitsa.ingest.cli day /path/to/incoming --out "$PWD/var/day-26" --ai embed
```

`KZ_USD_RUB` — согласованный курс для цен с меткой USD в заголовке, в колонке валюты или у суммы. Значение по умолчанию для демо — 100. Курс и число пересчитанных строк попадают в `catalog.currency`. Перед разбором коммерческого прайса задайте свой курс. Режим `embed` локальный, для отключения раскладки используйте `--ai off`. Для утверждённого живого прогона укажите `--ai jev --ai-budget-usd 0.20`.

Откройте `day_report.md`. Сверьте назначения файлов и баланс принятых и пропущенных строк. В `day_report.json` указаны заголовки, причины пропусков истории, число поисков с учётом частоты, итоги повтора и предложения агента. `coverage.recognized.all` — доля предложений, для которых в основной БЗ одновременно нашлись вендор, класс и семейство. Остальные доли считаются отдельно. Ниже приведены до 50 неизвестных вендоров и классов с частотами. Для слов из истории частота — число поисков, где встречалось слово. Самопроверка использует до 300 предложений, фиксированное зерно 7, группы известных и новых семейств и девять применимых видов проб.

В таблице файлов `day_report.md` различайте два отчёта Метрики.

| Подпись в отчёте дня | Как узнать выгрузку | Что учитывает `day` |
|---|---|---|
| Метрика · поиск по сайту (`metrika`) | Заголовок отчёта «Поиск по сайту» или колонка «Фраза внутреннего поиска» с показателями визитов | Запросы посетителей в поиске магазина для повторного прогона. |
| Метрика · фразы из поисковиков (`metrika_external_phrases`) | Колонка `ym:s:searchPhrase` вместе с `ym:s:visits`, как в файлах `03.tsv` | Визиты из внешнего поиска попадают в отчёт о привлечении. Повторный прогон использует только историю поиска магазина. |

Если назначение прайса или колонок ошибочно, сверьте образцы и повторите команду с `--mapping map.yaml` в новом `--out`. Формат карты приведён выше. Для истории проверьте наличие колонки запроса, для Метрики — полей визитов, отказов или заголовков Logs API. Поле `error` у источника сохраняет причину ошибки при чтении. Подробности качества каталога и очередь ручной проверки находятся в том же каталоге данных.

Для показа ведущий открывает витрину с `KZ_DATA_DIR=$PWD/var/day-26` и `KZ_CACHE_DIR=$PWD/var/day-26/cache`. Проверить снимок до переключения можно локально:

```bash
KZ_DATA_DIR="$PWD/var/day-26" KZ_CACHE_DIR="$PWD/var/day-26/cache" "$PY" -m kuznitsa.cli search 'антивирус на 30 пк' --mode fast
```

Репетиционные папки — [1С](ingest_examples/day_1c), [YML](ingest_examples/day_yml), [USD CSV](ingest_examples/day_usd). В каждом наборе файл с номером 01 содержит прайс, `02.csv` — историю поиска магазина, `03.tsv` — фразы из поисковиков. В режиме `embed` с новым кэшем весь цикл занял 82 с, 90 с и 87 с соответственно. Замеры по каждому набору приведены в [отчёте D3](../design/proposals/data/REPORT-D3.md).

**Если мало распознано.** Отдельно смотрите `recognized.family` (совпадение с основной БЗ) и `recognized.category` (доля наших категорий после раскладки). У совершенно нового ассортимента первое значение может быть нулевым даже при успешной раскладке. В `import_ai.jsonl` отберите решения с `accepted=false`, проверьте варианты и описание товара. Уточните путь магазина или укажите канонический листовой `category_id`; для раздела «Прочее» особенно важно описание каждой линейки. При повторе изменившиеся вопросы получат отдельные ключи кэша.

**Стоимость и очередь проверки.** В `import_report.json → ai` находятся фактические `sent`, `cached`, `usd`, причины понижения режима и до десяти примеров. Счётчики `accepted/rejected` включают локальные решения о признаках и аналогах. `questions` считает только задачи выбора категории, задачи пользователя, роли и отрасли. У `embed` значение `probability` — оценка сходства, у `jev` — вероятность выбранного варианта из ответа модели. Кандидаты в аналоги и признаки с `confidence=low` предназначены для проверки контент-менеджером.

### Как склеиваются прайс, остатки и варианты

Передайте всю папку в `day`. Для отдельной проверки каталога передайте связанные файлы вместе в `import-catalog`. В XLSX читаются все листы, ярусы заголовков и единицы измерения. Вложенные строки разделов задают путь категории до следующего раздела. Цена и количество могут содержать пробелы и десятичную запятую. В качестве справочника валют принимаются числовые курсы фида. Без курса неизвестной валюты цена переходит в режим запроса.

При объединении первая непустая ячейка основного прайса имеет приоритет, затем берутся значения фида и таблиц остатков. Идентификаторы сравниваются целиком. Для незнакомых заголовков проверяется пересечение почти уникальных значений из разных таблиц. В `import_report.json → merge` находятся обнаруженные ключи, число присоединённых строк, конфликты по полям и примеры обоих значений. Счётчик `inactive` и файл `inactive_offers.jsonl` сохраняют снятые позиции отдельно от продаваемых. В архиве указаны исходные коды, причина снятия и булевы поля `attrs.active`, `attrs.sold` со значением `false`. Статус снятой позиции и повторные строки показаны в `issues`. Столбцы `accepted` в отчёте дня считают также строки, обогатившие существующее предложение. Количество закупаемых предложений находится в `catalog.offers`.

| Форма | Что получится | Независимый образец |
|---|---|---|
| CommerceML 2.x | Группы классификатора, значения свойств и реквизитов наследуются вариантами по Ид товара. Характеристики и артикул варианта уточняют карточку. Для цены выбирается розничный тип, при его отсутствии первый тип из файла. Остальные цены сохраняются с подписями. Явное общее количество имеет приоритет перед суммой по складам. | [Пара XML](ingest_examples/day_commerceml) |
| API магазина | Вложенные варианты наследуют производителя, название и общие характеристики. Идентификаторы карточки и варианта сохраняются вместе. | [JSON с двумя вариантами](ingest_examples/day_variants/api.json) |
| Книга с отдельными ценами | Одна строка диапазона количества даёт одно предложение. У ступеней общий код товара, собственные границы, цены и стабильные внутренние идентификаторы. | [Книга с двумя листами](ingest_examples/day_bands/bands.xlsx) |

### Поля для поиска, приоритетов и КП

| Поле | Содержание |
|---|---|
| `source_id`, `source_ids` | Основной внешний код и список исходных кодов предложения, включая GUID, артикулы, код учётной системы, витрины, штрихкод и идентификатор родителя у вариантов. В КП есть колонка «Исходный код». Общий код семейства или ступени может относиться к нескольким предложениям. |
| `attrs.country`, `attrs.analog_of` | Страна разработки и указанный поставщиком продукт для замены. |
| `attrs.registry_no`, `attrs.certs` | Номер реестровой записи и обозначения явно указанных сертификатов. В `attrs.fstec` и `attrs.fsb` сохраняются исходные значения профильных колонок. |
| `attrs.operation`, `attrs.unit` | Формулировки поставщика для операции и единицы лицензирования. Распознанные значения доступны также в `lic`. |
| `attrs.qty_min`, `attrs.qty_max`, `attrs.term_months` | Границы применимости цены включительно и срок в месяцах. |
| `attrs.delivery`, `attrs.series`, `attrs.edition` | Исходные поставка, серия и исполнение. Канонические поля предложения остаются доступными отдельно. |
| `attrs.aliases`, `attrs.task` | Список поисковых синонимов из «Также ищут», «Жаргон», «Синонимы», «Ключевые слова» и текст назначения из «Решаемая задача», «Назначение». Назначение также заполняет пустое описание. |
| `attrs.extra` | Объект со значениями нераспознанных колонок под оригинальными именами. |
| `in_stock`, `delivery_days`, `added_at`, `promo`, `domestic` | Наличие, срок поставки (верхняя граница интервала в днях), дата ISO, участие в акции и отечественная разработка по явным данным. В исходном каталоге пропущенный признак обозначен `null`. Значения для приоритетов продублированы в `attrs`. |

При чтении снимков строковой схемы `Offer.attrs` декодируйте значения `aliases`, `certs`, `source_ids` и `extra` из JSON-строки. В схеме с поддержкой списков и словарей импорт записывает эти значения напрямую. Верхнеуровневый `source_ids` всегда массив. В `day_report.json` раздел `timings` содержит секунды по этапам. Для репетиции с явным ограничением числа повторяемых исторических фраз можно передать `--replay-limit N`. По умолчанию обрабатываются все принятые уникальные фразы. Долгий журнал и ответы повторного поиска сохраняются в отдельном выходном снимке.

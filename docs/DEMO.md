# Сценарий показа жюри — «Кузница Softline» (команда AiXenix)

Документ содержит два готовых маршрута живого показа — **на 5 минут** (жёсткий тайминг защиты) и **на 10 минут** (расширенное демо с шагами хода 4: спецификация файлом → КП, виджет `/embed`, ОКВЭД и голос), а также краткие ответы на пять базовых вопросов жюри (полный список из 24 вопросов — в `docs/QA-JURY.md`).

> **Числа стенда:** в документе приведены фактические показатели текущего стенда с указанием места в консоли, где ведущий их увидит. После финальной сборки ведущий при необходимости обновит их по тем же экранам. Режим `naive` везде называем **«Обычный поиск по словам»** (он не воспроизводит поиск настоящего магазина, а служит базовой точкой сравнения).

## Предстартовый чек-лист (за 2 минуты до показа)

1. Открыты три вкладки браузера: витрина `/`, админ-консоль `/admin` и демонстрация виджета `/embed`.
2. В правом верхнем углу витрины доступен переключатель профилей (`guest`, `smb_trade`, `gov_clinic`, `edu_university`, `ent_factory`, `it_company`, `design_bureau`, `accounting_firm`, `fin_bank`).
3. В `/admin → Агент` (фильтр «Контент-менеджер») открыта неприменённая карточка `add_synonym`: **«резервилка» → «Кибер Бэкап»**, готовая к нажатию «Применить» в эфире.
4. Включён режим поиска `smart`; под рукой переключатель сравнения с режимом «Обычный поиск по словам» (`naive`) и подготовленный файл спецификации `.xlsx`/`.csv` для 10-минутного маршрута.

## Пять частых вопросов жюри (быстрая шпаргалка)

Развёрнутые ответы на 24 вероятных вопроса жюри собраны в отдельном документе `docs/QA-JURY.md`. Ниже — пять самых частых вопросов прямо у экрана.

1. **Сколько стоит один умный запрос и как быстро он работает?**
   Быстрый режим (`fast`) стоит **0 ₽** и отвечает за **p50 6 мс, p95 22 мс**. Умный режим (`smart`) в среднем стоит **≈ 0,006 ₽** (**598 ₽** за 100 000 запросов, **≈ 180 ₽/мес** при 1 000 запросов в день по курсу 100 ₽/$), потому что до внешнего категоризатора `typesafe/jev-1.13` доходит около **40 %** запросов, а остальное решают локальные правила и кэш SQLite; задержка без кэша — **p95 ≈ 0,4 с**.
2. **Что будет, если внешний категоризатор откажет или пропадёт интернет?**
   Поиск не остановится и не вернёт ошибку: при таймауте, сбое сети или исчерпании дневного лимита `KZ_LLM_DAILY_BUDGET_USD` система бесшовно переключается на локальный режим `fast` (правила, база знаний, BM25, n-граммы и локальные ONNX-эмбеддинги с `HF_HUB_OFFLINE=1`).
3. **Почему это не «обёртка над LLM»?**
   Внешняя модель вызывается только как закрытый категоризатор — она выбирает идентификатор из ограниченного списка и не генерирует свободный текст. Вся выдача строится исключительно из товаров каталога и структурированной базы знаний, а на контрольном наборе даже полностью локальный режим `fast` даёт 291 из 310 (против 292 из 310 у `smart`).
4. **Почему продвижение маржи не сломает релевантность?**
   В ранжировании действует жёсткая изоляция 4 полос релевантности (Tier-Band Isolation): сортировка идёт сначала по полосе `(tier ASC)`, и только внутри полосы — по коммерческому скору. Дорогой, но менее релевантный товар физически не может обогнать точное совпадение, что подтверждает инвариант «Инверсий полос: 0».
5. **Как подключить решение к настоящему интернет-магазину?**
   Ядро и база знаний отделены от каталога: прайс загружается через адаптер импорта (CSV, JSON, XLSX, XML/YML), витрина подключается виджетом одной строкой (`/web/embed/widget.js`) или через REST API (`/api/search`, `/api/suggest`, `/api/events`). Пилот на реальном прайсе поднимается за 1–2 недели.

## Выявленные причины провалов

1. **Два разных пути для обычного и исправленного ввода.** Старая `kuznitsa/plans/feed.py::suggestions` применяла разные ветки до и после `repair`, из-за чего раскладка (`цшт` вместо `win`, `fdnjrfl` вместо `автокад`, `ajnj` вместо `фото`) и опечатки вели в другой код или обнуляли ответ.
2. **Неполное разворачивание семейств, вендоров и разделов KB в индекс подсказок.**
   - `FeedIndex.tags["families"]` пропускал семейства со скобками и вариантами в `name` (например, `Microsoft Office (2021 / 2024 / LTSC)`, `Postgres Pro (Standard / Enterprise / Certified)`), из-за чего словарные термины (`постгрес`, `ворд`, `эксель`) не находили карточки.
   - `FeedIndex` привязывал каждую задачу `kb/feed_tasks.yaml` только к первой секции (теряя `Российские операционные системы` для `os_linux`, часть секций для `office_suite` и т. д.), а `index.tags["classes"]` для широкой секции «Программы для защиты информации» подмешивал посторонние карточки (`Kaspersky Security для виртуальных сред`, `Стахановец`) в выдачу категорий `e_signature` (`эцп`) и `endpoint_security` (`антив`).
   - В `kb/slang.yaml` записи вида `win10 -> {platform: windows}` стирали версию `10`, а `ноут` / `ноутбук -> {platform: windows}` мешали распознаванию оборудования.
   - Компоненты пакетов из `kb/feed_analogs.yaml` с `in_catalog: false` (`ms_word`, `ms_excel`, `postgresql`) перехватывались как «отсутствующий товар» раньше сопоставления с имеющимися в каталоге семействами (`Microsoft Office`, `Postgres Pro`).
   - Длинные юридические названия вендоров в фиде (`Программы и лицензии Microsoft Corporation`) не сопоставлялись с коротким именем `Microsoft` (`micr` уходил в `Microolap` / `MicroSurvey`), а для `Яндекс` поиск только по латинскому `Yandex` пропускал «Яндекс 360 для бизнеса».
3. **Неучёт значимости, начала названия и разнообразия вендоров.**
   - Совпадение по префиксу слова без разделения «точное начало названия / бренд / раздел / оборудование» приводило к показу нишевых карточек (`АвтоКаталог` на `авток`, `ФотоШОУ PRO` на `фотош`, `WINE@Etersoft` на `win`, `Defender Офисное кресло` на `оф`, `Модем Zyxel` на `резерв`, `Сертификат техподдержки` на `антивирус`).
   - В разделах один вендор занимал 3–4 позиции из 4 (`VK WorkSpace` на `офис`, `Red Hat` на `линукс`), вытесняя остальные бренды раздела.
4. **Числа, сроки и служебные слова обнуляли подсказки.** Вводы «кас 10», «касперский 10 пк», «купить каспер» не очищались от служебных слов/тиража/срока при сохранении версий продукта («windows 10», «office 2021», «windows 11 p»).
5. **Повторы карточек и пробел во фронтенде.** Допродажи (`upsell`) не исключали уже показанные `card_id` из `products`. В `web/js/suggest.js` отсутствовала группа `analogs` (при этом `corrections` и клавиши `ArrowUp`/`ArrowDown`/`Enter`/`Escape` уже были реализованы).

## Что изменено

- **`kuznitsa/plans/feed_suggest.py`** (новый модуль):
  - `FeedSuggestIndex`: одноразовое построение предрасчитанных отсортированных структур по началам слов (`title_keys`/`title_rows`, `entity_keys`/`entities`, `section_keys`/`sections`, `family_cards`, `kb_cat_cards`, `kb_cat_task_secs`, `kb_cat_keywords`, `short_vendor_map`, `typo_match`, `roman_to_term`) без тяжёлых вычислений и без вызовов MiniLM на нажатие клавиши.
  - Единый конвейер `suggestions(engine, raw, norm, profile, start)` → `FeedSuggestIndex.interpret(...)`, а при пустом результате — `repair_query(...)` (раскладка → транслитерация/фонетика → опечатка Дамерау-Левенштейна) и повторный проход через ту же `interpret(...)`.
  - Приоритет толкования: редакция (`index.edition`) → аналоги отсутствующего товара (если нет прямого семейства в каталоге) → лицензирование → очистка служебных слов/тиража/срока (`_strip_modifiers`) → оборудование / задача / раздел с уточнением (`_section_with_qualifier`) → точное начало названия продукта → бренд / семейство / русские написания → раздел / синонимы / категории KB / оборудование → совпадение по токенам с префиксом.
  - Порядок внутри бренда делегирован в `index.products(...)` и `index.quality` (совместимо с N3 без дублирования списка флагманов); для разделов добавлено разнообразие по вендорам (`_diversify_by_vendor`) и учёт ключевых слов раздела/категории.
  - Сквозная дедупликация `card_id` между `products` и `upsell`; для бессмысленного ввода (`xyzq`) возвращается пустой список групп.
- **`kuznitsa/suggest/index.py`**:
  - В `SuggestIndex.__init__`: инициализация `self.feed_suggest = FeedSuggestIndex(catalog.feed, kb, lex)` при `catalog.is_feed`.
  - В `suggest(...)`: переключение делегирования фидовых подсказок с `kuznitsa.plans.feed.suggestions` на `kuznitsa.plans.feed_suggest.suggestions`.
- **`kb/slang_n5.yaml`** (новый файл данных БЗ, 21 термин без повторов существующих `term`, проверен по `real-cards.tsv` и `kuznitsa.kb.loader.load`: 0 предупреждений, 0 ошибок):
  - Дополнительные русские написания для `Postgres Pro`, `Microsoft SQL Server`, `Adobe Photoshop Pro`, `CorelDRAW`, `nanoCAD`, `TeamViewer`, `КриптоПро`, `КриптоАРМ ГОСТ`, `Dr.Web Security Space`, `МойОфис`, `Яндекс 360`.
- **`web/js/suggest.js`**:
  - Добавлена поддержка группы `analogs` (`groups`, `titles`, `caps`, карточный рендер с фото/ценой и переходом на `/card/<id>`). Проверены `corrections` и навигация клавишами `ArrowUp`/`ArrowDown`/`Enter`/`Escape`.
- **`tests/test_n5_suggest.py`** (новый файл, 26 тестов на маленьких выдуманных карточках):
  - Покрыты все 9 пунктов задания: единый путь с исправлениями (`цшт == win`, `rfcg == касп`, `fdnjrfl == автокад`, опечатки), толкование незаконченного ввода (бренды, русские написания, разделы, оборудование), порядок и значимость (`office`, `micr`, `sql`, `secret`, `autoc`, `оф`), числа/сроки/служебные слова и версии, тип товара с уточнением и `queries`, дедупликация и пустой ответ на `xyzq`, скорость и предрасчётный индекс, `analogs` и проверка групп/клавиш в `web/js/suggest.js`.

## Остаток (зависимость от N3)

До слияния с N3 остаются несданными ровно **3 из 91** вводов — все три относятся к порядку главных продуктов внутри бренда Kaspersky (сейчас `index.products("kaspersky")` / `index.quality` отдают первыми `Kaspersky Security для виртуальных сред` и `Kaspersky Security для систем хранения`, а после слияния N3 начнут отдавать `Kaspersky Standard`, `Plus`, `Premium` и `Small Office`):

1. `касп` — проверка `not4=виртуальных|хранения`
2. `каспер` — проверка `not4=виртуальных|хранения`
3. `касперский` — проверки `top=kaspersky (standard|plus|premium|small office); not2=виртуальных|хранения`

Второй список главных продуктов намеренно не заводился согласно требованиям задания; `FeedSuggestIndex._vendor_products` берёт порядок напрямую из `index.products(...)` и `index.quality`, поэтому после слияния N3 все 3 ввода пройдут автоматически.

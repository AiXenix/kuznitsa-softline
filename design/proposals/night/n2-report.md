## 3. Разобранные причины сбоев и архитектура решения

### 3.1. Корневые причины (почему база давала 10/50 по `задача` и 7/16 по `вопрос`)

1. **Перехват железными словами внутри софтовых задач.** В запросах вроде *«резервное копирование сервера»*, *«удаленный доступ к компьютеру сотрудника»*, *«мониторинг серверов»*, *«шифрование дисков ноутбуков»* слова *сервер / компьютер / ноутбук* раньше перетягивали выдачу в разделы железа (`feed_query` / классификатор железа). При этом запросы вида *«ноутбук для бухгалтера»* или *«сервер для 1С»* обязаны оставаться железными.
2. **Разрыв между языком бизнес-задачи и структурой разделов каталога.** В фиде `store.softline.ru` релевантные продукты для одной задачи разбросаны по разным веткам (например, DLP лежит в *«Контроль персонала»* и *«Информационная безопасность»*, сметы — в *«Документообороте»* и *«Инфраструктуре»*, WAF/DDoS — в *«Интернет и Сеть»* и *«Межсетевых экранах»*). Раздел фида сам по себе зашумлён второстепенными/вспомогательными карточками (курсы, сертификаты ТП, книги).
3. **Вопросительные обёртки (`что поставить…`, `какую программу выбрать…`, `чем заменить…`, `сколько стоит…`, `что есть у…`).** Обёртки засоряли лексический и векторный поиск, мешая распознавать как задачи, так и конкретные продукты/вендоров и замены.
4. **Аббревиатуры и англоязычные запросы.** Короткие ИБ/ИТ-термины (`siem`, `dlp`, `vdi`, `skzi/скзи`, `edr`, `mdm`, `waf`, `pam`, `ddos`) и англоязычные задачи (`backup software for servers`, `antivirus for 10 users`) либо портились автоисправлением опечаток, либо не извлекали количество (`10 users`, `50 человек`).
5. **Комплексные задачи (комплекты «под ключ»).** Запросы типа *«организовать рабочее место бухгалтера»*, *«открываем новый офис на 20 человек»*, *«переводим офис на удалёнку»* требуют подборки из нескольких классов ПО с пояснением состава комплекта, а не одного узкого раздела.

## 7. Известные ограничения и рекомендации на развитие

1. **Перехват родовых существительных в `product_context()`.** На запросе *«система для удаленного подключения к пк сотрудников»* префикс *«система …»* совпал с заголовками карточек (`Система водяного охлаждения …`, `Система управления очередью …`) в `product_context()` раньше `resolve_solution()`. Рекомендуемый follow-up: добавить родовые слова (*система, программа, платформа, решение, комплекс, средство, сервис, утилита*) в стоп-список префиксов `product_context()` (или пропускать `product_context`, если найдено многословное совпадение `SolutionIndex`).
2. **Поддержка `check_snapshot()` в `kuznitsa.cli kb-check`.** В рамках N2 файл `kuznitsa/kb.py` намеренно не изменялся, чтобы не пересекаться с другими потоками; при слиянии стоит подключить вызов `feed_solutions.check_snapshot(kb, cfg.kb, cfg.data)` внутрь `kb-check`, чтобы регрессии по `pins`/`sections` на новых снимках фида ловились автоматически.
3. **Различие морфологии глагол/существительное.** Лемматизация pymorphy даёт разные леммы для пар *защита / защитить*, *перевод / перевести*, поэтому сейчас в `kb/feed_solutions.yaml` указаны обе формы для ключевых сценариев. При расширении базы полезно добавить компактный словарь отглагольных основ или стемминг поверх `SolutionIndex.cues`.
4. **Интеграция с `smart`-режимом.** `SolutionIndex` и `resolve_solution()` работают в общем конвейере `FeedPlan`, не ломая `smart`-режим и ускоряя обработку типовых задач без лишнего обращения к LLM.

# Отчёт по треку N9: параметры оборудования, производитель/серия, расходники и совместимость

## 1. Причины исходных провалов

Анализ 10 крупнейших аппаратных разделов в снимке `real/v1` (8 125 предложений, 7 300 карточек оборудования в 165 аппаратных разделах) и разбор провалов `cases2.tsv` (`железо2`: 7/20 на стенде, 12/20 на стволе) выявил системные причины:

1. **Параметры в запросах не разбирались и уводили поиск в посторонние разделы или ПО**:
   - Запросы с параметрами (`ssd 1 тб`, `ноутбук 16 гб i7`, `монитор 27 дюймов 4k`, `флешка 64 гб`, `оперативная память ddr5 32gb`, `роутер wi-fi 6`, `коммутатор 24 порта`, `мфу лазерное цветное`, `ибп 1000 ва`) не имели структурного разбора параметров, поэтому «лишние» слова уводили запрос в `named_subject`, `noise_clean`, словарь аналогов (`feed_analogs`) или полнотекстовый поиск по ПО (Microsoft SQL / Dr.Fone / PowerDVD / VentaFax / DesignJet).
   - Числа при устройстве без единицы измерения (`монитор 27`, `ssd 500`, `коммутатор 24`) не различались с количеством (`ноутбук 5 шт`) и ценой (`ноутбук до 60000`).
2. **Неоднородная запись параметров в фиде (`title`, `description`, `attrs`)**:
   - В названиях видеокарт/накопителей встречается греческая буква `Γ` (`16 ΓБ` вместо кириллической `ГБ`), смешение `1 ТБ` / `1TB` / `1000 ГБ` / `1024 ГБ` и номинальных объёмов (`960`, `480`, `240` ГБ).
   - У комплектов ОЗУ в `attrs` хранятся `Ёмкость одного модуля` и `Количество в комплекте` (например, `2 × 16 ГБ = 32 ГБ`).
   - У 4K-мониторов атрибут `Разрешение` в фиде часто ошибочно содержит `FullHD`, тогда как истинное разрешение `3840x2160` указано в `description`.
   - У ноутбуков нового поколения процессоры записаны как `Core 7` / `Core Ultra 7` без префикса `i` (`i7`).
   - У роутеров стандарт Wi-Fi 6/7 чаще виден по модельному коду (`AX`, `BE`) и диапазону `6.0 ГГц`, а число портов коммутаторов — по `description` (`24 × 10/100 port`, `24xGE`).
3. **Многословные имена производителей и отсутствующие бренды**:
   - В каталоге производители оборудования имеют `vendor_id` вида `hp inc.`, `dell technologies`, `tp-link`, `d-link`, `western digital`.
   - В `resolve_hardware_section` из `q_set` вычиталось `{vendor}` целиком вместо `set(words(vendor))`: для `сервер dell` слово `dell` оставалось в `q_set` и уводило запрос из `86563` (`Rack-серверы`, 0 серверов Dell) в `78997` (`Жесткие диски` Dell).
   - Для отсутствующих в разделе производителей (`сервер dell`, `коммутатор cisco 24 порта`) требовалось оставаться в разделе оборудования с честным пояснением, а не показывать чужие разделы.
4. **Расходные материалы, аксессуары и совместимость**:
   - Для `картридж для hp laserjet`, `тонер для kyocera`, `блок питания для ноутбука asus`, `чехол для ipad` требовалось попадать в раздел расходников/аксессуаров и поднимать совместимые с целевым устройством модели выше остальных (не выводить сам принтер HP первой карточкой).
   - Для `чехол для ipad` извлекатель платформ ПО (`feed_conditions.py`) снимал «для ipad» как платформу ПО, теряя цель совместимости.
5. **Шум и добор чужих разделов в малых аппаратных категориях**:
   - В разделе `98055` (`Графические планшеты`) среди карточек была ошибочно классифицированная акустическая система, а `fill()` подмешивал в малые разделы (`Графические планшеты`, `Проекторы`, `Чехлы для планшетов`) товары из соседних разделов (`Canon`, колонки).
   - В составных разделах (`88831` «Наушники и микрофоны», `94694` «Расходные материалы», `78997` «Жесткие диски», `93995` «Принтеры и МФУ») требовалось уточнить подтипы (`наушники с микрофоном` → гарнитура, `тонер`, `жёсткий диск` без SSD, `мфу` без плоттеров DesignJet).

## 2. Изменённые и добавленные файлы и функции

### Новые файлы
- [`kb/hardware_specs.yaml`](file:///home/bb/kuznitsa-softline-n9/kb/hardware_specs.yaml) — декларативный словарь ~40 типов оборудования, расходников и аксессуаров (`feed_classes`, `section_keywords`, `triggers`, `bare_number_spec`, `bare_number_range`, `gb_role`, `is_consumable`, `implied_specs`), словарь известных аппаратных брендов (`known_brands`, включая отсутствующие в фиде — `Cisco`, `Apple`, `HPE`, `Keenetic`, `Wacom` и др.), модельных серий (`model_series`: `thinkpad`, `laserjet`, `ecosys`, `odyssey`, `archer`, `fury` и др.) и русских подписей параметров (`spec_labels`).
- [`kuznitsa/index/hardware_specs.py`](file:///home/bb/kuznitsa-softline-n9/kuznitsa/index/hardware_specs.py):
  - `OfferSpecs`, `HardwareQuery` — структуры предвычисленных параметров карточек и разобранного аппаратного запроса.
  - `_extract_offer_specs(...)`, `_merge_offer_specs(...)` — однократное извлечение параметров всех аппаратных предложений из `title`, `description`, `attrs` при сборке индекса (нормализация греческой `ΓБ`, `1 ТБ = 1000 ГБ = 1024 ГБ`, комплекты ОЗУ, приоритет пиксельного разрешения над `FullHD`, `Core 7`/`Core Ultra 7` → `i7`, `AX`/`BE` → `Wi-Fi 6`/`7`, порты коммутаторов, тип/цвет/формат печати, мощность Вт/ВА, токены совместимости и признак универсальности).
  - `HardwareSpecIndex(feed_index, kb_dir)` — индекс параметров карточек оборудования (165 разделов, 7 300 карточек, время сборки **0.94 с**).
  - `HardwareSpecIndex.parse_query(...)` — разбор запроса по единицам измерения и словарю (`kb/hardware_specs.yaml`): количество `N шт` (до голых чисел), совместимость расходников/аксессуаров, разрешение, Wi-Fi, DDR, CPU, GPU, объём/ОЗУ, мощность Вт/ВА, порты, диагональ, формат бумаги, 1U–6U, печать/цвет, интерфейсы, производитель/серия, голые числа при устройстве, учёт `req.ignore` (`"specs"`, `"spec:<k>"`), строгий фильтр против ПО (`_SOFTWARE_GUARD_RE`, `_PO_FOR_RE`) и торгового оборудования (`_TRADE_QUALIFIER_RE`).
  - `HardwareSpecIndex.apply(...)` — фильтрация/ранжирование внутри раздела оборудования по производителю, совместимости, модельному ряду, подтипу и параметрам (с выбором подходящего `preferred`-предложения в мульти-офферных карточках); при отсутствии точного совпадения — честное пояснение в `agent_note` и сортировка по ближайшим числовым значениям без выхода из раздела.
  - `HardwareSpecIndex.populate_result(...)` — запись распознанных параметров в `understood.filters["specs"]`, установка `understood.qty` для `N шт` и генерация съёмных значков `understood.chips` (`key="spec:<k>"`, `removable=True`).
- [`tests/test_n9_hardware_specs.py`](file:///home/bb/kuznitsa-softline-n9/tests/test_n9_hardware_specs.py) — 7 комплексных тестов на синтетическом мини-фиде: объём/единицы/ближайшие, ОЗУ/DDR/CPU/диагональ/4K/голые числа vs количество vs цена, сеть/печать/мощность, производители и модельный ряд (включая отсутствующие бренды), расходники и совместимость (включая `чехол для ipad` и `блок питания для ноутбука asus`), `understood.filters["specs"]` + съёмные `chips` через `req.ignore`, малые разделы и защита от перехвата ПО.

  - Поддержка `"specs"` и `"spec:*"` в `req.ignore`.

  - Вызов `index.hardware_specs.populate_result(hw_query, result, chips)`.

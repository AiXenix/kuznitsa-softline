# Отчёт по треку N4: условия покупки, сравнения, периферия

## 1. Причины исходных провалов

1. **Условия покупки (`условия`: 9/18 → 17/18)**:
   - В `kuznitsa/plans/feed.py` разбиралась только верхняя граница цены через `split_budget` («до N»), а при пустом пересечении с границей `feed.py` жёстко обнулял `ids = []` (`zero_reason="filters_too_strict"`), либо пропускал запрос мимо фида (`return None`).
   - Не извлекались и не применялись: нижняя граница («от N», «дороже N»), диапазоны («от N до M», «N–M»), сортировка по цене («самый дешёвый», «самый дорогой»), исключения вендоров/продуктов («кроме Microsoft», «не касперский»), фильтр происхождения/реестра («российский», «отечественный», «из реестра»), платформа («для mac», «для android»), техподдержка/внедрение («техподдержка Astra Linux») и апгрейд версий («апгрейд windows 10 до 11» ошибочно воспринимался как цена `до 11`).
   - Офисные запросы с бустом/исключением («офис кроме microsoft», «российский офисный пакет») попадали в узкий раздел только с Microsoft или поднимали не-офисные инструменты (Workspad) выше полноценных офисных пакетов («МойОфис», «Р7-Офис»).
2. **Сравнения (`сравнение`: 0/7 → 7/7)**:
   - В `feed.py` запросы со словами «сравни…» отсекались регулярным выражением `COMPLEX`, а конструкции «X или Y», «X vs Y», «что лучше X или Y» не распознавались как сравнение двух продуктов/редакций (включая усечённую правую часть вида `kaspersky standard или plus`, `windows 11 home vs pro` и случаи, когда одна сторона отсутствует в каталоге, как `сравнить dr.web и eset`).
3. **Оборудование и периферия (`железо`: 12/13 → 13/13; плюс `принтер hp` в `условия`)**:
   - Для `принтер hp` функция `vendor_class` находила раздел `91774` («Торговое оборудование / Принтеры», 0 карточек HP) вместо `93995` («Офисная техника / Принтеры и МФУ», 82 карточки HP), из-за чего срабатывал ложный `vendor_gap` («В разделе «Принтеры» товаров этого производителя нет»).
   - В составных разделах периферии (`82833` «Клавиатуры, мыши, комплекты», `88831` «Наушники и микрофоны», `94694` «Расходные материалы», `78997` «Жесткие диски») ранжирование по `index.quality` поднимало комплекты (`клавиатура+мышь`), микрофоны, фотобарабаны и плёнку для ламинирования выше точного типа устройства из запроса (`клавиатура`, `мышь`, `наушники`, `гарнитура`, `картридж`, `жёсткий диск`).

## 2. Изменённые и добавленные файлы

### Новые модули
- `kuznitsa/plans/feed_conditions.py`:
  - `extract(engine, norm, req)` — извлечение из текста запроса (и слияние с `Request`) условий покупки: апгрейд версий (`UPGRADE_RE`, до парсинга цены), ценовые диапазоны и границы (`price_min`, `price_max` с защитой от версий и единиц количества/срока), сортировка (`price_asc` / `price_desc`), исключения (`exclude_vendors`, `exclude_terms` с кешированным поиском по `kb/vendors*.yaml` и `index.vendor_names`), происхождение и реестр (`origin="russian"`, `registry=True` без перехвата запросов аналогов), техподдержка/внедрение (`service`), платформа (`platform` только при известном предмете каталога, чтобы не ломать `not_in_catalog` для неизвестных брендов вроде `FableMuse для Mac`).

- Единственный оставшийся провал в группе `условия` — `касперский на 2 года` (ранжирование массовых линеек Kaspersky Standard/Plus/Endpoint выше узкоспециализированных серверных решений) относится к зоне ответственности трека N3 (`ранжирование продуктов`).

## Второй заход

### 1. Причины провалов на новом стволе и чистка слияния

1. **Бюджет и реестр (`cases2.tsv`, `бюджет` 8/10 → 10/10, `реестр` 8/11 → 10/11; `cases.tsv`, `условия` 17/18 → 18/18)**:
   - В `kuznitsa/plans/feed.py` ветка `_search_solution(...)` не получала `cond` и не вызывала `feed_conditions.apply_conditions` / `populate_result`. Из-за этого `российский офисный пакет`, `недорогой офисный пакет` и `офисный пакет из реестра отечественного по` попадали в `office_suite` без фильтрации по происхождению/реестру и без сортировки по цене.
   - `resolve_solution(...)` перехватывал запросы `отечественный антивирус` и `российский мессенджер для компании` через `kit_import_substitution` (фразы «российское по» / «отечественное по» после лемматизации сводятся к одному слову `российский`/`отечественный`).
   - В `feed_conditions.py` не обрабатывались запросы бесплатных версий (`бесплатный антивирус`, `антивирус даром`), а при фильтрации по реестру (`cond.registry`) пустое пересечение по редко заполненному флагу `o.registry` откатывало фильтрацию и пропускало зарубежных вендоров (Microsoft Office).
   - Добор из соседних разделов по домену при `origin="russian"` срабатывал даже на уже заполненных разделах (например, «Антивирусы для организаций»), подмешивая СКЗИ (КриптоПро, Рутокен).
2. **Текстовые исключения (`check_request.py --group исключения`: 7/7 текстовых)**:
   - Не разбирались минус-слова (`антивирус -касперский`) и цепочки вендоров (`ноутбук кроме asus и acer`).
   - В `recommend(...)` в `feed.py` не передавался список исключённых карточек (`blocked`), из-за чего исключённый производитель просачивался в допродажи (`upsell`/`crosssell`).
3. **Несколько продуктов в одном запросе (6/6 + 6/6 защитных)**:
   - `feed_compare.py` разбирал только явные сравнения и «или»/«vs», а связки `&`, `+`, `/`, запятая и «и» между двумя опознанными продуктами или классами уходили в одиночный поиск или посторонние товары.
4. **Чистка после слияния с N1 и N3**:
   - Дублирующий механизм `soft_budget` / `budget_relaxed` из N1 в `feed.py` сведён к единому механизму в `feed_conditions.apply_conditions(...)`: текстовый ценовой потолок при пустом пересечении честно показывает ближайшие доступные карточки (`price_relaxed=True`), а явный API-фильтр `req.filters["price_max"|"price_min"]` остаётся строгим (`zero_reason="filters_too_strict"`).
   - Условие `or not re.search(r"[a-z]", cand)` в `extract()` заменено на точную проверку `_is_software_subject(index, engine, cand)`: программный предмет проверяется по `software_sections`, `products(domain="software")`, `edition`, `slang`, `vendor_names`, `solutions` и `class_terms` при явном отсечении `index.hardware`. Проверено: `антивирус для mac` → `platform=['macos']`, `антивирус для android` → `platform=['android']`; `игра для mac`, `чехол для айфона`, `мышь для mac` — без ложного фильтра `platform`.

### 1. Причины и исправления

1. **Допродажа к ИБП (`kb/upsell_r9.yaml`, `kuznitsa/rank/upsell.py`, `kuznitsa/plans/feed.py`)**
   - *Причина*: в `kb/upsell_r9.yaml` правило `hw_ups_batteries` объединяло классы `[82014, 82661, 131130]` в один список без приоритета класса, поэтому по общему `quality` вперёд выходили «Сетевой фильтр PC Pet AP01006» (`82661`) и PDU (`131130`); дополнительно `recommend()` вставлял в ленту хвост `extra[-split:]`, переворачивая порядок приоритетов.
   - *Исправление*: правило разделено на три приоритетных правила — `hw_ups_batteries` (`82014`, weight `0.94`), `hw_ups_surge` (`82661`, weight `0.84`), `hw_ups_pdu` (`131130`, weight `0.80`); в `upsell.py::compile()` добавлен учёт порядка классов `class_order`, в `interleave()` сохраняется порядок приоритетов кандидатов, а в `feed.py::recommend()` в основную ленту вставляется голова `extra[:split]` (в блок `crosssell` — `extra[split:split+6]`).
   - *Проверка на `real/v1` (5 разных карточек ИБП: `Powercom WOW WOW-300 / 850U / 500U / 700U / 1000U`)*: на всех 5 первой плиткой допродажи идёт «Сменная батарея для ИБП Delta DTM» (`82014`), «Сетевой фильтр PC Pet AP01006» (`82661`) и «для ИБП Lanmaster PDU» (`131130`) идут после (в `crosssell`).

2. **Программный продукт + «для компьютеров / для ноутбуков / для сервера / в офис» (`kuznitsa/plans/feed_conditions.py`, `kuznitsa/plans/feed_query.py`, `kuznitsa/plans/feed.py`, `kb/upsell_r9.yaml`, `kuznitsa/rank/upsell.py`)**

В `kb/upsell_r9.yaml` добавлены правила `alt_linux_backup`, `ru_os_av`, `ru_os_backup`; в `upsell.py` снят префикс «операционная система » при сопоставлении семейств и добавлен fallback по `vendor_aliases`.

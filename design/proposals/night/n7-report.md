# Отчёт по треку N7: сортировка, фильтры, исключения, фасеты и страницы на настоящем каталоге

## 1. Причины исходных провалов

На стенде со старым кодом (`request-base.txt`: **32 из 95**; целевые группы N7: `страницы` 7/8, `сортировка` 0/12, `фильтры` 5/14, `исключения` 3/10, `фасеты` 0/8) проблема складывалась из шести системных причин:

1. **Уход запросов с параметрами в старый конвейер `Engine._search`:**
   - В `kuznitsa/plans/feed.py::search` стоял отсекающий фильтр `if ... req.filters.keys()-{"price_max","price_min","origin","registry"} or req.exclude ...: return`, из-за которого любые запросы с `filters.vendor`, `filters.category`, `filters.platform`, `exclude.vendor`, `exclude.category` или `ignore` по этим ключам возвращали `None` и проваливались в старый конвейер `Engine._search`, не знающий структуры фида (отсюда посторонние карточки вроде «Блок питания Ippon E90» на ноутбуках и ложные «нет в каталоге»).
   - Аналогично `resolve_solution` в `feed_query.py` отказывался разбирать задачи («резервное копирование») при наличии `sort`/`filters`/`exclude`, а `feed_guard.build_vendor_result` («всё от X / продукты X») не применял фильтры, исключения, сортировку и не строил фасеты.
2. **Некорректная сортировка и смешивание с допродажами:**
   - Сортировка применялась без учёта сквозного порядка по `card.price_from` на всём подходящем списке (а также зависела от выбранного оффера и мерчандайзинга), и в ответ при явной сортировке подмешивались допродажи и добор `fill()`.
   - `kuznitsa/schema.py::Request.sort` принимал произвольную строку `str | None` вместо перечисления допустимых значений, из-за чего неизвестное значение `sort` не отклонялось с HTTP `422`.
3. **Нестрогая фильтрация и ложный фоллбэк на параметрах `filters` / `exclude`:**
   - `feed_conditions.apply_conditions` рассчитан на мягкие текстовые условия (например, «windows дешевле 15000» — при пустом результате откатывается к ближайшим по цене карточкам, а при текстовом исключении и `< 4` карточках добирает соседние разделы; кроме того, `req.exclude["vendor"]` попадал в `exclude_terms` и отбрасывал чужих вендоров по слову в названии). Для явных параметров `Request.filters` и `Request.exclude` требовалась строгая фильтрация по `card.price_from`, `index.card_vendors` и `index.card_sections` с честным пустым ответом, `zero_reason="filters_too_strict"` и подсказками `relax_hints` без подмешивания посторонних товаров.
4. **Отсутствие групп уточнения (`facets`):**
   - `kuznitsa/plans/feed.py` всегда возвращал `facets=[]` на фиде.
5. **Повтор допродаж на страницах > 1:**
   - `recommend()` вызывался на каждой странице, повторяя один и тот же блок «Вам может пригодиться» на второй и последующих страницах.
6. **Неполное отражение применённых параметров в `understood`:**
   - Параметры `vendor`, `category`, `exclude` не попадали в `understood.filters`, `understood.exclude` и съёмные значки `understood.chips` (`removable: true`), а `ignore=["vendor"]` не снимал ограничение по производителю.

## 2. Изменённые и добавленные файлы

### Новые файлы
- `kuznitsa/plans/feed_request.py` — единая обработка параметров запроса N7 и расчёт групп уточнения поверх `feed_conditions.py` (без дублирования разбора текста):
  - `RequestPlan` — структура объединённого плана (текстовые `Conditions` из `feed_conditions.extract` + явные параметры `filters`, `exclude`, `sort`, `ignore`).
  - `unsupported(req)` — проверка параметров, поддерживаемых планом фида (`SUPPORTED_FILTERS`, `SUPPORTED_EXCLUDE`, `SUPPORTED_IGNORE`, `sort in ("price_asc", "price_desc")`).
  - `for_solution(req)` — передаёт в `resolve_solution` очищенную копию запроса без параметров N7, чтобы задачи (например, «резервное копирование») распознавались одинаково с параметрами и без них.
  - `_vendor_lookup(index)` и `resolve_vendors(index, engine, raw_values)` — кешируемое на индексе разрешение кодов (`vendor.id` / `index.card_vendors`) и названий производителей в любом регистре (точное совпадение, `casefold`, `normalize`, `words`, `index.vendor_names`, `feed_conditions._resolve_exclude` только по `vids`, без текстовых `exclude_terms`).
  - `extract(engine, norm, req)` — делегирует разбор текста исключительно в `feed_conditions.extract()` на копии запроса без параметров, затем складывает текстовые условия с параметрами `req.filters`, `req.exclude`, `req.sort` с учётом `req.ignore` в общий `Conditions` и `RequestPlan`.
  - `_filter_ids(...)` и `apply(...)` — строгий конвейер: текстовые условия через `feed_conditions.apply_conditions` (сохраняя мягкий фоллбэк N4 для текстовых цен) → снимок `base_ids` для фасетов и `relax_hints` → строгие фильтры (`vendor` OR, `category` OR, `price_min`/`price_max` по `card.price_from`, `origin`, `registry`, `platform`; AND между разными ключами) и исключения (`exclude.vendor`, `exclude.category`) → при нулевом пересечении честный пустой список + пояснение + `_build_relax_hints(...)` → сквозная сортировка всего подходящего списка `sort_ids(...)` по `card.price_from` (карточки без цены в конце).
  - `prepare_page_offers(...)` и `finish_items_sort(...)` — подбор офферов только на текущей странице и сохранение строгого ценового порядка после мерчандайзинга `order()`.
  - `allow_upsell(req, plan, items)` и `allow_fill(req, plan)` — допродажи только на `page == 1`, не при сортировке и не на пустом ответе; добор похожих отключён при фильтрах, исключениях, сортировке и `page > 1`.
  - `_price_thresholds(prices)` и `build_facets(...)` — расчёт групп уточнения `vendor` (до 12 по числу товаров, при ≥ 2 значениях), `category` (при ≥ 2 разделах, до 12) и `price_max` (3–5 округлённых порогов вида «до 5 000 ₽» с целочисленным `id` и точным `count` через `bisect_right`, равным `total` после выбора). Каждая группа считается по списку с учётом всех остальных фильтров и исключений, но без своего ключа; отключается на пустом ответе, сравнении и «нет в каталоге».
  - `populate_result(...)` — вызывает `feed_conditions.populate_result(...)`, добавляет в `understood.filters`, `understood.exclude` и `understood.chips` съёмные значки (`removable: true`) для `vendor`, `category`, `platform`, `exclude`, а при пустом результате после фильтров выставляет `zero_reason="filters_too_strict"`, `relax_hints` и блок `clarify`.
  - `build_vendor_result(...)` — обёртка поверх `feed_guard.rank_vendor_cards` для каталога производителя («всё от X / продукты X») с полной поддержкой `sort`, `filters`, `exclude`, `page` и `facets` (без правок `feed_guard.py`).
- `tests/test_n7_request_params.py` — 9 интеграционных и модульных тестов на синтетическом фиде (валидация `sort` и HTTP 422, сквозная сортировка по нескольким страницам с `None` в конце и без допродаж, фильтры `vendor`/`category`/`price_min`/`price_max` с OR/AND и сложением с текстом, пустой ответ с `filters_too_strict` и `relax_hints`, точные исключения `exclude.vendor`/`exclude.category` без ложного срабатывания по названию чужого товара, фасеты `vendor`/`category`/`price_max` с лимитом 12, точными счётчиками и независимостью от собственного фильтра, `understood`/`chips`/`ignore`, пагинация и допродажи только на странице 1, каталог производителя, задачи и отсутствие фасетов на сравнении).

### Изменённые файлы (минимальные вставки)
- `kuznitsa/schema.py` (+2/−1 строки):
  - Добавлен тип `Sort = Literal["price_asc","price_desc"]`, поле `Request.sort` ограничено типом `Sort | None = None` (неизвестные значения `sort` возвращают HTTP `422`).
- `kuznitsa/plans/feed.py` (+50/−33 строки):
  - В `_search_solution`: принятие `plan: RequestPlan`, прогон через `feed_request.apply`, `prepare_page_offers`, `finish_items_sort`, `allow_upsell`, `build_facets`, `populate_result`.
  - В `search`: вызов `feed_request.extract`, проброс `feed_request.for_solution(req)` в `resolve_solution`, делегирование каталога производителя в `feed_request.build_vendor_result`, замена условия отсечения на `feed_request.unsupported(req)`, снятие `vendor`/`supplier` при `"vendor" in plan.ignore`, вызовы `feed_request.apply`, `prepare_page_offers`, `finish_items_sort`, `allow_fill`, `allow_upsell`, `build_facets` и `populate_result`.

### Рекомендации для `kuznitsa/plans/feed_conditions.py` (файл не редактировался из-за параллельной работы N4)
Реализовано обёрткой в `feed_request.py`; при последующей консолидации N4 + N7 в `feed_conditions.py` стоит учесть два момента:
1. В `feed_conditions.extract()` параметр `req.exclude["vendor"]` сейчас добавляется в `exclude_terms`, из-за чего текстовое сопоставление по заголовку способно отбрасывать карточки других вендоров, упоминающих исключённый бренд в названии; явный `req.exclude["vendor"]` должен сопоставляться только по `index.card_vendors`.
2. В `feed_conditions.apply_conditions()` ценовой фильтр при пустом пересечении откатывается к ближайшим карточкам (нужно для мягких текстовых запросов N4), а при исключениях с `< 4` карточками добирает соседние разделы; для явных параметров `Request.filters`/`Request.exclude` нужен строгий режим (без фоллбэка и добора, с точным сравнением по `card.price_from`).

**Контракт для A и E.** Исходный `<offer id>` лежит в `attrs.feed_offer_id`, `source_id` и `source_ids`. В `source_ids` также входит непустой `vendorCode`. У 44 978 предложений артикул производителя указан. У остальных в `sku` хранится код предложения магазина. Самопроверка учитывает поиск по такому коду отдельно от поиска по артикулу.

`attrs.group_id` содержит строку фида или пустую строку. `family_id` и идентификатор карточки равны группе. Одиночная карточка получает идентификатор `sku_<feed_offer_id>`. Общее начало названий вариантов даёт название карточки. Если от него осталось только имя вендора, используется название линейки из дерева.

`attrs.feed_category_id` равен исходному `categoryId`. В этой версии XML он указывает на **класс**. `attrs.feed_category_path_ids` — JSON-массив строк от корня к листу. Группа продолжается до третьего уровня, когда её ID есть в классификаторе и её родитель совпадает с классом предложения. У 8 125 одиночных карточек XML даёт два уровня. Текстовый путь лежит в `category_path`. Поля `attrs.root_id`, `attrs.class_id`, `attrs.line_id` позволяют обращаться к уровням напрямую. В `category_id` записан принятый лист БЗ или `auto_sl_<класс фида>` для класса, требующего проверки. Например, у Adobe InCopy группа и линейка — `556`, путь — `["8","127","556"]`, исходный класс — `127`, раздел БЗ — `text_editors`.

В JSON сохранены `url`, `vendorUrl`, `picture`, `sales_notes`, обе цены и доступность. Пустая старая цена остаётся пустой. Нулевая цена сохраняется вместе с `price_on_request=true`. Предложений с положительной ценой — 55 771, доступных — 44 601. У 32 позиций выполнено `0 < price < oldprice`. Сверка исходных идентификаторов, путей, URL, изображений, цен и доступности прошла по каждой строке XML.

```bash
export HF_HUB_OFFLINE=1 KZ_LLM=off OPENBLAS_NUM_THREADS=1

"$PY" -m kuznitsa.ingest.cli day /home/bb/kuznitsa-softline-ops/hack-data/in-feed \
  --out var/day-softline-new --ai jev --ai-budget-usd 0.30 --n 300

export KZ_CACHE_DIR="$KZ_DATA_DIR/cache"
"$PY" -m kuznitsa.cli search 'kaspersky small office security' --mode fast
```

**Для A.** Перед переходом к `off_topic`, уточнению раздела или фиксации единственной редакции проверьте совпадения в именах и алиасах активных групп, вендоров и линеек фида. Для «кибер бэкап» используйте сочетание вендора и класса, для «мтс» — префикс вендора и его карточки, для «365» — числовой токен названия при отсутствии точного артикула. Сравните версии Office по словам полной строки продукта перед применением фильтра аудитории.

В `kuznitsa/index/source.py::read_offer` включите `"feed_category_path_ids"` в исключения последнего цикла сериализации `attrs`, чтобы массив исходных ID оставался списком в памяти. Направление доступно через `offer.attrs["domain"]`, исходные уровни отдельно — через `root_id`, `class_id`, `line_id`. В `Catalog` при расчёте минимальной цены карточки исключайте предложения с `price_on_request` и нулевой ценой. Это позволит показать реальную минимальную цену среди вариантов, где цена известна.

# D6 · Номенклатура и цены 1С:УТ, история из API и чата

## Приём каталога

В каждой из трёх книг 1С:УТ команда `day` приняла три товара и присоединила три строки из отдельного прайса. В каталоге получились две дочерние категории и один товар в корне. Группы и промежуточный итог остались за пределами списка предложений. Проверены уровни группировки Excel, отступ ячейки наименования и ссылки через «Родитель», в том числе товар, записанный раньше родительской группы. Для пустой папки, у которой есть только код и название, надёжный признак — колонка «Это группа».

Характеристики в одной ячейке разбираются по парам «ключ — значение». В примере у «Север CAD» сохранились производитель «Вектор», серия «Север», редакция «Проф», срок 24 месяца, ступень 10–49 пользователей, страна Россия и реестровая запись № 75001. Проверены также пакет из пяти лицензий и бессрочная лицензия.

Прайс соединяется по коду или артикулу. Для `VX-001` розничная цена составила 1 250,50 ₽, в `attrs.prices` сохранились «Оптовая» 1 050,50 ₽ и «Для госзаказчиков» 1 100,50 ₽. Отдельный тест проверяет объединённую шапку цен и отсутствие розничной цены при заполненной специальной.

**Для A.** Ведущий записывает в `<снимок>/segment_price_types.json` соответствие сегмента профиля точному названию вида цены, например `{"gov":"Для госзаказчиков"}`. При расчёте выдачи и КП используйте `offer.attrs["prices"][название]` для выбранного предложения. Если соответствие или сумма отсутствуют, применяйте обычный расчёт по `offer.price`. Команда назначения проверена на собранном снимке. [Инструкция ведущего](../../../docs/DAYX.md)

## МойСклад

Из пяти JSON-файлов собрано **четыре предложения**. Две самостоятельные позиции пришли с двух страниц ассортимента. Ещё две — модификации одного товара. Одна модификация повторялась внутри товара и на отдельной странице. Две группы восстановили путь «Программы / Проектирование». Из четырёх строк остатков присоединились три. Обратный порядок файлов дал те же четыре предложения с совпадением всех полей. В отчёте видны исходные количества строк и смещения страниц. [Образец выгрузки](../../../docs/ingest_examples/day_moysklad)

Поиск по UUID, коду, артикулу и внешнему коду вернул правильное предложение первым **в 16 из 16 проверок**. Общие коды родителя сохранены у обеих модификаций. Собственная цена 40 055 коп. стала 400,55 ₽. При складском остатке 10 и доступном количестве 0 предложение получило признак отсутствия. Проверены также отдельный `entity/product` и короткая выгрузка `stock` со связью по коду. [Схема отчёта об остатках МойСклад](https://github.com/moysklad/api-remap-1.2-openapi-specification/blob/master/src/components/schemas/report/stockAll.yaml)

## История

`day` принимает роли `metrika_api` и `support_chat` из `history.sniff`. Все страницы и чат проходят через один пакет `history.ingest_files`. В таблице дня выводятся квитанции B по каждому файлу. На совместном прогоне с кодом B6 две страницы по две строки дали **четыре уникальные строки** внешних поисковых фраз и **десять визитов** по итогу отчёта. CSV с датой, покупателем и сообщением дал **два обращения**. Эти файлы добавили ноль поисковых сессий магазина. Общий прогон 1С:УТ, МойСклад, Метрики и чата принял все десять файлов и собрал семь предложений. [Образцы истории](../../../docs/ingest_examples/ut_history)

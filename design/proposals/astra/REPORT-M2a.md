# M2a. Поиск и лицензии

AiXenix · поток A · исходная точка `d32db75`.

## Что изменилось

- Загрузчик объединяет семейство с поправками до проверки ссылок. Витринные названия хранятся отдельно от исходных поисковых имён и алиасов. У ролей, отраслей и задач рекомендации берутся из `families`. Для прежних записей с `products` семейства разрешаются через лексикон.
- Генератор учитывает единицу цены, редакцию, ступень количества, вместимость пакета, срок, действие и аудиторию. Без указанного тиража обычная лицензия имеет `calc.qty = null` и `calc.total = null`. Продление может взять количество из купленной лицензии, а комплект — из размера организации. Для Windows Server ядра рассчитываются с обязательным базовым пакетом, для другой пакетной продажи подбирается минимальная сумма покрытия. Переход за предел мест купленной младшей линейки получает цену новой покупки и пояснение.
- Доступны все 20 намерений. Поиск использует слоты комплектов, связи задач и аналогов, FAQ, регуляторные фильтры, лицензии организации, построчный подбор и сравнение характеристик. В цепочках хранится контекст на 15 минут. У сопутствующих предложений есть причина подбора. Для части ограничений при скудной выдаче доступен расчёт, сколько карточек вернёт их снятие.
- Публичные карточка и профиль доступны через `GET /api/card/{card_id}` и `GET /api/profile/{id}`. Снимки реальных ответов находятся в `docs/api_examples/`. В каталоге примеров есть комплекты, таблица спецификации, ответ FAQ, сравнение, акция и сопутствующие позиции.
- `eval` сравнивает машинные условия из `assert`, сохраняет результат каждой строки и даёт ожидаемое и фактическое значения при расхождении. Итоги по ключам и сценариям доступны в JSON вывода и в SQLite `eval_runs(id, ts, mode, dataset, result_json)`.

## Как воспроизвести

Из корня проекта, с локальной моделью.

```bash

$P -m pytest -q
$P -m kuznitsa.cli kb-check

$P -m kuznitsa.cli eval eval/queries.dev.jsonl --mode fast
$P scripts/check_scenarios.py --mode fast
$P scripts/make_api_examples.py
```

## Jev и учёт для потока B

Клиент держит соединение HTTPX, ждёт подключения до 2 с и ответа до 6 с. Повтор разрешён при ошибке установления соединения. В одном процессе одновременно допускаются два обращения. После пяти последовательных ошибок новые обращения приостанавливаются на 60 с. При недоступности, исчерпании бюджета или ошибке формата движок возвращает локальную выдачу с пояснением. Кэш доступен и без ключа.

В `smart` порог принятия выбора равен 0,55. Модель выбирает среди переданных движком намерений, категорий и вопросов FAQ. Для реранка движок передаёт до 30 отобранных карточек с выбранными лицензиями пачками по 20. Точное название и точный SKU обходят реранк. В `fast` обращений к Jev нет. Тесты клиента, вероятностного порога, параллельных пачек, кэша, бюджета и размыкателя используют подставной транспорт.

| Таблица | Столбцы и смысл |
| --- | --- |
| `llm_calls` | `id`, `ts` (Unix UTC), `search_id`, `kind` (intent или rerank), `model`, `cached` (0/1), `tokens_in`, `tokens_out`, `cost_usd` (из usage.cost), `ms`, `ok` (0/1), `source` (источник поискового запроса). Попадание в кэш записывается с нулевой стоимостью. Отказ предохранителя тоже оставляет строку с ok=0. |
| `llm_cache` | `key` (SHA-256 от модели, состояния и вопросов), `kind`, `schema_hash` (SHA-256 от вопросов с вариантами), `response_json` (проверенный словарь answers), `cost_usd` (стоимость исходного ответа), `created_at` (Unix UTC), `hits` (число повторных использований). |

Дневной лимит магазина задаёт `KZ_LLM_DAILY_BUDGET_USD`, по умолчанию 3 USD. У прогона оценки свой бюджет. Команда живой проверки — `.venv/bin/python -m kuznitsa.cli eval eval/queries.dev.jsonl --mode smart --budget-usd 1` при заданном в окружении `OPENROUTER_API_KEY`. При отсутствии `usage.cost` для оценки по входным токенам используется `KZ_JEV_PRICE_IN`, в трассе появляется признак `estimated`. Рубли пересчитываются по `KZ_USD_RUB`. Ответ поиска содержит число внешних решений, попаданий в кэш и фактическую стоимость. Интеграция этих величин в общую строку журнала и сводку шага `log` принадлежит потоку B.

### Что увидит покупатель

- У торгового клиента куплен KSOS на 15 устройств. На «каспер продление» поиск подбирает пакет на 15 и считает 15 990 ₽. На «каспер продление на 30 компов» результат меняется на Kaspersky Endpoint Security для бизнеса, новая покупка: 30 × 2 470 ₽ = 74 100 ₽. Причина перехода указана в ответе.
- «Офис для 20 сотрудников» приводит в листовую категорию офисных пакетов. В проверке для гостя первой была лицензия МойОфис Стандартный для бизнеса с расчётом 20 × 2 800 ₽ = 56 000 ₽.
- «Чем заменить Microsoft Office» открывает блок аналогов. На карточке кандидата без заданного тиража отображается ставка на пользователя, сумма заказа остаётся пустой.

### Записи галереи с расхождениями

Проверка сравнивает заявленный `intent` с фактическим и ищет непустой блок ожидаемого вида. Семь демонстраций админки в полном знаменателе относятся к потоку B. У них отсутствует поисковый запрос. Это горячий лид, растущий спрос, пробел каталога, пробел словаря, дефект карточки, волна продлений и правило маржи.

| Запись | Что происходит в поиске |
| --- | --- |
| `license_addon_expansion`, `addon_vs_new_by_ownership` | Галерея ожидает `renewal`. Поиск трактует дополнительные места как `license_ops`, проверяет варианты докупки и условия владения. |
| `restricted_vendor_query` | По Windows 11 Pro есть SKU. Подбор возвращает `product`. В галерее указан `out_of_catalog`. Совместный показ доступного товара и отечественных замен остаётся на M2b. |

| `keyboard_layout_error` | Исправленная раскладка даёт название вендора «касперский». Выводится `vendor`, в галерее указан `product`. |

### Контракт и остаток на M2b

- Поля запросов, названия сценариев и формы основных блоков сохранены. Для смешанного набора пакетов `calc.items` содержит конкретные SKU, количество и цену каждой позиции. `calc.unit_price` в таком случае равна `null`. При неполной спецификации или отсутствии подтверждённой цены итог может быть `null`.
- Для услуг и акций в `items` передаются обычные карточки. Семь административных демонстраций, перенос `cost` и `inherited` в общую аналитику проверяются после слияния потоков.
- Качество живых решений Jev и воспроизводимость на кассете требуют прогона с ключом. У уже начатых параллельных вызовов итоговая стоимость известна после ответа. Дневной лимит останавливает новые решения по учтённым затратам.
- Остаются разбор плоского каталога и названий чужих SKU, привязка реестровых номеров из подтверждённого источника, точная совместимость при добавлении второго продукта, полное покрытие подсказок снятия условий и оставшиеся расхождения dev. Текущие подсказки считают альтернативы для платформы, модели, редакции, срока, сертификатов, реестра и верхней границы цены.
- Пакетная формула и прогноз суммы показывают демонстрационные цены. Коммерческое право на продление или переход между линейками требует подтверждения условий вендора. В показательных профилях покупок сохранены исходные наименования. Историю поисков и выгрузки Метрики генерирует поток B.

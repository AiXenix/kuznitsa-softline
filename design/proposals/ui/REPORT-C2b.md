# C2b · Консоль бизнеса и инспектор

Для показа на 1366 × 768 начните с `/admin#head`. На первом экране помещаются обе пары полос, размер парной выборки и три оценки потерь. Следующий кадр — `/admin#agent?type=add_synonym&status=new&first=1`. Регламент выбирает предложение из API и сохраняет в адресе его ID. Ведущий открывает доказательства, применяет предложение и нажимает «Проверить». С каждой стороны сравнения есть ссылка на сохранённую трассу.

## Сделано

| Раздел | Что видит жюри |
|---|---|
| Руководитель | Прежний поиск и Кузница на одной истории, прогноз потерь и формулы, плитки и графики по московским дням. Предпросмотр весов показывает изменение позиций, маржи и число инверсий. Есть сохранение весов, экономика при заданной нагрузке и качество на проверках. |
| Менеджер e-com | Воронка по наблюдаемым поискам, CTR, отказы и переформулировки, три подборки запросов, причины, лиды и продления. Создание семи видов правил, переключение, удаление и открытие проверочного запроса. |
| Продукт | Текущий и предыдущий периоды спроса, абсолютный прирост, сортируемые срезы по сценариям, категориям и сегментам, спрос на ушедшие продукты и воронка замен. |
| Контент | Кластеры пробелов, сегменты и оценки потерь, разбивка по вендорам и категориям, карточки с пропущенными полями и предложения редактору. |
| Агент | Виды, роли, статусы, приоритет и сортировка по оценке эффекта. Примеры фраз, сессии, сегменты, куда переходили клиенты, действие и формула эффекта. Применение, отклонение, повторный прогон и обновление находок из журнала. |
| Журнал и инспектор | Состав по источникам. На B1 журнал открывает доступные агрегаты. Полный ответ показывает раскрытые шаги слева и сохранённую выдачу справа. В архивной сводке доступен повторный поиск. |

Применены существующие компоненты карточек и трассы. Графики построены встроенным SVG. Шаги показа используют адреса действующих вкладок. Изменения консоли находятся в `web/js/admin/`, общая оболочка и оформление — в `web/js/pages.js` и `web/css/store.css`. Контракты и параметры описаны в `docs/UI.md`.

В `kuznitsa/pages.py` добавлены прямой путь к карточке каталога и небольшой защищённый поиск ID по фразе. Это закрывает ссылки из B1 там, где агрегат содержит только текст. Переход ведёт к последней записи по точному q_raw, проверяет доступ тем же authorize, что и служебный API. Исходные обработчики потока B менять не требуется.

## Проверки

- Все шесть вкладок открыты в Chrome на отдельной копии снимка каталога и журнала. Проверены экран руководителя, архивная запись и полная запись с 15 раскрытыми шагами.
- С временным локальным ключом проверены apply, verify, reject, refresh, предпросмотр и сохранение весов, создание, выключение и удаление правила. Изменённые веса в тестовой копии составили 0,45 + 0,22 + 0,165 + 0,165. Без ключа интерфейс поясняет требование, при неправильном ключе показывает осмысленный HTTP 403.
- По предложению для «адешка» было повторено пять фраз. Изменение выдачи показано для каждой фразы. Наличие ALD Pro на первом месте исходного поиска видно в сравнении.
- Тесты `tests/web/test_admin_console.py` сверяют пути и методы с приложением и проверяют авторизацию переходов по тексту. Отрисовщики прогнаны в Chrome на `docs/admin_examples`, пустых списках, null, нулевых знаменателях и примерах дополнительных B2-полей. Тест подставляет новое значение метрики в ответ и проверяет текст экрана.
- Полный набор pytest — **123 passed**, одно предупреждение Starlette TestClient. Все 24 JS-модуля прошли `node --check`. Временный сервер остановлен, сеанс браузера закрыт.

## Передача потоку B

1. Для recent нужны точное время, q, search_id, профиль и сегмент, режим, intent, n_cards, ms и стоимость с указанной валютой. Поддержка этой выборки уже есть, на текущем B1 сервер отвечает 422.
2. У failures.example, gaps.queries и insight.evidence.sample_queries полезен собственный search_id для каждого наблюдения. Поиск последней одноимённой записи точен по тексту, но она может относиться к другой сессии или дате.
3. Полный сохранённый ответ B1 часто не содержит ts и общего числа карточек для нетоварного блока. У verification.before/after доступно число сохранённых верхних позиций, для полного сравнения полезно отдельное n_cards.
4. Для KPI нужны абсолютные counts каждого этапа воронки, единицы pairs и направление улучшения. В B1 счётчики кликов, корзин и заказов для воронки восстанавливаются округлением behavioral_searches × доля. Денежные оценки берутся целиком из ответа.
5. Для стоимости полезны число фактически отправленных внешних вызовов и число кэш-попаданий. Число requests по режиму само по себе этого не объясняет.

## Наблюдения по снимку

На проверенном снимке парный прогон покрывает 3 000 фраз и 35 459 исторических поисков. Доля пустых выдач изменилась с 72,8 % до 12,6 %. Для top-5 знаменатель меньше — 33 793 размеченных поиска. Эти величины относятся к повтору на синтетической истории.

Базовая оценка потерь около 8,48 млрд ₽, осторожная около 5,54 млрд ₽, оценка для восстановленной выдачи около 3,51 млрд ₽. При выручке из поисков около 34,3 млрд ₽ эти суммы заслуживают проверки медианного чека и вклада крупных сессий. На экране они подписаны как оценки потенциала.

В истории «адешка» фигурирует как пробел словаря, хотя текущий движок на том же тексте уже ставит ALD Pro первым до применения правила. Для демонстрации восстановления из нуля стоит отбирать находку с фактическим восстановлением в verify. Даты синтетических запросов доходят до 21 ноября, поэтому последняя запись по фразе может быть архивной даже после нового живого повтора. Подтверждений роста реальных заказов из парного прогона сервер не возвращает.

Живой B2 в этой копии отсутствует. Поддержка pairs и recent проверена подстановкой ответов в браузерном тесте.

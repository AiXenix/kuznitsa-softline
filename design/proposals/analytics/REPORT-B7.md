# B7 · перенос аналитики на тестовый стенд

AiXenix · 26 ноября 2026 · проверяемый выпуск `b3fa17a`.

## Причина пустого экрана

На коде выпуска проверка совместимости воспроизводит сообщение из консоли при открытии исходного `real/v1`. В нём 4 741 служебный поиск, **0 исторических** и активный прогон `be3fc43d16e11e07801a1c94` на 0 фраз. В записи этого прогона отпечаток метода начинается с `82918934`, у выпуска — с `59f80bb2`.

В готовом `real/v2` есть 45 000 исторических поисков, 5 384 записи eval и 1 119 записей replay. Активен прогон `7a800801e83fcd643da662f2`, его отпечаток совпадает с кодом выпуска. Старый прогон тоже лежит в SQLite. Консоль выбирает прогон по `kv['settings:active_replay']`. Даты в исходной истории есть — с 29 августа по 26 ноября по Москве.

Число 4 809 на экране меньше 6 503 служебных записей готового v2. Оно исключает чтение свежего ответа из полной копии этого журнала. Скрипт `test_deploy.sh` без `KZ_TEST_SNAP` выбирает `real/v1`, а открытая вкладка держит GET-ответы до «Обновить». Точный источник ответа работающей службы проверяется в `/api/admin/ingest → sources` после обновления вкладки. Каталог службы и её окружение в этой проверке не использовались.

**Что проверяет выпуск.** Для feed сравниваются режим источника, SHA-256 байтов каталога, разметки, кода генератора и метода сравнения. Запись генерации включает модель, зерно, опорную дату и число строк. Отпечаток генератора складывается из `querylog_gen.py`, `naive.py`, `text.py` и `feed_history.py`, метода — из `replay.py`, `rollup.py` и `engine.py`. Для импортированной истории идентификатором редакции служит метка времени записи источника. Пути данных и кэша, права и inode в сравнение не входят. Время изменения каталога участвует в выборе идентификатора при **запуске** replay. Чтение готового прогона проверяет сохранённые отпечатки содержимого.

**Что исправлено.** На выпуске график читал дни из парного KPI. Любое предупреждение о совместимости скрывало также даты, а ограниченный replay сужал график до выбранных фраз. Теперь график отдельно суммирует поиски и долю пустых выдач по московским дням из `active_history`. Служебные и живые события в эту выборку не попадают. При несовместимости консоль указывает отсутствие истории в подключённом журнале либо конкретное расхождение версии.

## Процедура для оператора

Готовый `real/v2` подходит для выпуска `b3fa17a`. Для повторной сборки в новой копии запустить из корня кода выбранного выпуска, с путём к установленной локальной модели:

```bash
set -e -o pipefail
src=/home/bb/kuznitsa-softline-int
rev=$(git -C "$src" rev-parse HEAD)
code=$(mktemp -d)
git -C "$src" archive "$rev" | tar -x -C "$code"
cd "$code"
P=/home/bb/kuznitsa-softline/.venv/bin/python
KZ_DATA_DIR=$(mktemp -d /home/bb/kuznitsa-softline-ops/real/b7.XXXXXX)
export KZ_DATA_DIR
cp -a /home/bb/kuznitsa-softline-ops/real/v2/. "$KZ_DATA_DIR/"
export KZ_CACHE_DIR="$KZ_DATA_DIR/cache" KZ_MODEL_DIR=/home/bb/kuznitsa-softline-analytics/var/models
export KZ_LLM=off HF_HUB_OFFLINE=1
"$P" -m kuznitsa.cli gen-history --feed --today 2026-11-26 --seed 20261126
"$P" -m kuznitsa.cli gen-metrika
"$P" -m kuznitsa.cli replay --mode fast
"$P" -m kuznitsa.cli insights
```

Архив фиксирует один выпуск на все четыре команды, даже если ветка движется во время сборки. Копировать завершённый снимок целиком после выхода всех четырёх команд. Журнал, `catalog.jsonl` и `mock_truth.jsonl` должны лежать непосредственно в `KZ_DATA_DIR`. Для уже готового v2 точный выбор источника штатной выкладки:

```bash
test "$(git -C /home/bb/kuznitsa-softline-int rev-parse --short HEAD)" = b3fa17a &&
  KZ_TEST_DATA=copy KZ_TEST_SNAP=/home/bb/kuznitsa-softline-ops/real/v2 \
    bash /home/bb/kuznitsa-softline-ops/test_deploy.sh
```

Скрипт сам упаковывает текущий HEAD копии `kuznitsa-softline-int`. Команда с готовым v2 рассчитана на выпуск `b3fa17a`. Если HEAD уже другой, использовать собранную выше копию и запускать выкладку из той же оболочки:

```bash
test "$(git -C "$src" rev-parse HEAD)" = "$rev" &&
  KZ_TEST_DATA=copy KZ_TEST_SNAP="$KZ_DATA_DIR" bash /home/bb/kuznitsa-softline-ops/test_deploy.sh
```

Строка `data from …` в выводе скрипта должна содержать выбранный каталог. Скрипт назначает служебного пользователя владельцем копии, включая закрытый для других пользователей `mock_truth.jsonl`. В шапке открытой консоли нажать «Обновить». Для контроля сверить строку истории в `ingest.sources`, затем `kpi.comparison.run_id` и `ui/history-days.period`.

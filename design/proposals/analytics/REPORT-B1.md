# B1 · Аналитика «Кузницы Softline»

AiXenix, ветка `analytics`. На парной выборке старый поиск дал пустую выдачу в **52,85%** случаев, «Кузница» — в **15,21%**. В 15 688 исторических поисках фраза впервые дала хотя бы одну карточку. Проверка агента сопоставила с эталоном **15 из 18** сюжетов. Доступны все восемь видов предложений.

## Как показать за минуту

1. Открыть предложение **«Связать „резервилка“ с запросом „Кибер Бэкап“»**, ID `add_synonym-57f1770cf0da`. В доказательствах посмотреть сессии и фразы, которыми посетители заменяли исходный запрос.
2. Применить и проверить. На той же сборке движка запросы «резервилка» и «лицензия резервилка» дали по одной карточке «Кибер Бэкап» после пустой выдачи. По запросу «корпоративная резервилка» целевой товар также оказался в выдаче. Ни одна из проверенных фраз не потеряла непустой результат. Сохранены исходные и повторные трассы.
3. На экране руководителя показать парный replay и открыть формулу рублёвой оценки. Эксперимент измерил доступность результата и попадание в нужное семейство или категорию. Конверсию после внедрения предстоит измерить по заказам покупателей.

Первая проверка с автоматической контрольной точкой SQLite обнаружила длинный хвост задержки. Запись теперь использует одно постоянное соединение, WAL и `synchronous=NORMAL`. ## Что именно измерено

| Показатель парного прогона | Прежний поиск | Кузница fast |
|---|---:|---:|
| Пустые выдачи / 41 672 поисков | 22 025 · 52,85% | 6 337 · 15,21% |
| Цель в первых пяти / 39 739 поисков с эталоном | 19 396 · 48,81% | 33 068 · 83,21% |

В 13 712 случаях цель вошла в первую тройку после промаха прежнего поиска. Для одинаковой фразы учитываются разные цели покупателей и их частоты. Неизвестные внешние запросы без эталона исключаются из знаменателя целевой метрики. Сравнение выдач выполняется для нейтрального профиля.

На всей исходной истории конверсия в заказ составила 2,29%, в корзину 5,13%, CTR первых трёх позиций 23,56%. Средняя позиция клика 2,25. Уходом закончились 52,05% неудачных поисков. Доля переформулировок 33,11%. В журнале 1 029 заказов на 486 883 407 ₽, маржа 126 733 986,89 ₽.

Осторожная оценка потерянных заказов на всей истории — **182 040 261 ₽**, базовая — 282 977 094 ₽. Из осторожной оценки **110 124 158 ₽** приходится на сессии, для которых replay восстановил непустую выдачу. Расчёт исключает сессии с корзиной, заявкой или заказом, повторную атрибуцию и нецелевой спрос. Для среза используются конверсия успешных сессий, медианный чек и показанный в API коэффициент причины. Это сценарная оценка на синтетических ценах и размерах закупок. Отдельные эффекты предложений пересекаются.

## Хранилище и швы

| Таблица | Содержимое |
|---|---|
| searches | ID, время, сессия и клиент, сегмент, источник, движок, режим, запрос и его разбор, категория, количество карточек, причина, верх выдачи, блоки, стоимость, задержка. `prev_search_id` связывает уточнения. `response_z` содержит полный JSON ответа с трассой в zlib. Старые строки читаются со сводкой и `trace_json`. |
| events | ID события, связь с поиском, сессия, клиент, действие, карточка и SKU, позиция, количество, стоимость, маржа, JSON деталей. |
| rules | ID, вид, условия, действие и активность. |
| insights | Стабильный ID, вид, статус, полная карточка JSON, сохранённая проверка JSON. |
| replays / replay_results | Параметры и отпечаток эксперимента, ожидаемое число фраз. Уникальный ключ результата — прогон и фраза. Поиск и результат одной фразы фиксируются в общей транзакции. |
| kv | Общая схема `(key, value, updated)`. Версия правил, веса, локальные задачи, списки кампаний и метаданные импортированных визитов. |
| llm_calls / llm_cache | Принадлежат потоку A. Стоимость вычисляется по зарегистрированным вызовам. |

Для подключения B1 **вставок в общие файлы не требуется**. Действующие швы загружают CLI, маршрутизатор и RuleControls. Генератор использует спецификацию и актуальный каталог. Для поиска наивными подстроками он заранее сужает кандидатов по длиннейшему обязательному слову, затем вызывает исходный `match` с сохранением порядка SKU.

Для будущего закрепления карточек **внутри блока analogs** потоку A потребуется одна замена в `Engine._search` файла `kuznitsa/engine.py`. Сейчас для `out_of_catalog` в `merch` поступает пустой список и результат перестановки отбрасывается. Заменить участок от `merch=self.controls.merch(...)` до `cards=merch["cards"]` включительно следующими двумя строками, сохранив последующую обработку `fired` и нумерацию.

```python
        merch=self.controls.merch(ctx,cards)
        cards=merch["cards"]
```

## Границы данных

Генератор воспроизводит сессии, сезонность, словарь запросов, темы и поведение на фактически найденных SKU. Проценты и чеки из сюжетов — ориентиры для проектирования данных. Часть профилей из спецификации ещё отсутствует в сборке каталога. В импортированных отчётах используются только переданные сведения, а для агрегированной частоты создаются синтетические наблюдения. Импорт отдельных визитов, затем хитов поддерживается. Хиты внутри визита обрабатываются в хронологическом порядке.

Проверка предложения фиксирует фактические изменения выдачи сразу после применения. Для контентной заявки, списка продлений и горячего лида подтверждением коммерческого эффекта будет последующее действие сотрудника и заказ. Заявки сохраняются локально. Форматы файлов организаторов и данные о последующих заказах предстоит проверить после их выдачи.

## Сборка для стенда

Выполнить в слитой основной копии. Новый каталог изолирует журнал и правила показа. Передать выведенный `KZ_DATA_DIR` стенду.

```bash
cd /home/bb/kuznitsa-softline
set -e
P="$PWD/.venv/bin/python"
export HF_HUB_OFFLINE=1 KZ_LLM=off
export KZ_DATA_DIR="$(mktemp -d "$PWD/var/data-b3-XXXXXXXX")"
"$P" -m kuznitsa.cli build-mock --seed 20261126 --today 2026-11-21
"$P" -m kuznitsa.cli build-index
"$P" -m kuznitsa.cli gen-history --seed 20261126 --today 2026-11-21
"$P" -m kuznitsa.cli gen-metrika
"$P" -m kuznitsa.cli replay --mode fast
"$P" -m kuznitsa.cli insights
printf 'KZ_DATA_DIR=%s\n' "$KZ_DATA_DIR"
```

Журнал фиксирует SHA-256 каталога и целей, версию генератора и сборку парного прогона. При расхождении или отсутствии отметок консоль получает пустые пары и одну строку `note`. [Ответ старому снимку](../../../docs/admin_examples/kpi-stale.json)

**A и C.** Дословные вставки для A переносят подготовку индекса в конструктор движка для прямых клиентов Python. Для C подключаются проекции в `pages.py` и сравнение по `card_ref || card_id`. Ключ строки `sku:<offer_id>` открывает конкретную поставку. Для кнопки скачивания адрес — `/api/admin/digest?role=${role}&format=xlsx`. [Патч, проверенный git apply --check](integration-B3.patch)

**D.** В сценарии данных организаторов после импорта каталога и построения индекса источником пар становится загруженная история. Отчёт раскладки и очередь появляются после `import-catalog`. Выполнить на том же `KZ_DATA_DIR` следующие команды.

```bash
"$P" -m kuznitsa.cli import-history "${HISTORY_FILES[@]}"
"$P" -m kuznitsa.cli replay --mode fast
"$P" -m kuznitsa.cli insights
```

Теперь строка поясняет отсутствие сведений о заявках. На контрольном импорте с CRM и GA4 проверены две связанные заявки и один заказ в двух поисках с заказом или заявкой.

## Решения для менеджеров

В исходном снимке было семь предложений. Три совета исправить карточки опирались на запросы по категории. Например, «РЕД ОС продление» попало в доказательства спроса на совместимость. Теперь проверяются формулировка требования покупателя и конкретная дефектная карточка в первой пятёрке. Старые неподтверждённые советы исключены и из сводок ролей. У подборки «Хранение» только проверка фразы «R-Tools Technology хранение» показала отсутствие нужного направления в пятёрке. Эта фраза встретилась один раз за 23 поиска по направлению. Для совета о растущем направлении теперь нужны хотя бы две сессии с проверенной фразой, а в денежную оценку входят потери только по таким фразам. После обновления агента на текущем движке осталось три предложения с историческими идентификаторами поисков, проверкой выдачи и формулой эффекта.

| Действие | Основание | Оценка |
|---|---|---:|
| Проверить поставку WinRAR | 57 поисков в 57 сессиях за 30 дней, проверочная выдача пуста | Потенциал 1,54 млн ₽, осторожно 0,85 млн ₽ |
| Развить подборку по тестированию ПО | Рост с 16 до 27 поисков за два равных окна | Потенциал 0,56 млн ₽, осторожно 0,33 млн ₽ |
| Проверить увеличение веса маржи | Девять перестановок, ноль нарушений уровня соответствия | +17 412 ₽ к взвешенной марже на выборке, осторожно 0 ₽ |

В выгрузке отсутствует журнал показов карточек. Раньше редактор видел 243 карточки с нулевыми показами. Теперь очередь упорядочена по числу поисков с зарегистрированным кликом. У первых трёх карточек 643, 615 и 533 таких поиска. В Markdown и XLSX подписана единица измерения. Проверены десять файлов для пяти ролей, включая лист «До и после» у руководителя и воронку у менеджера e-com. Файлы проверки сохранены в `var/b5-e1/reports-b5/`.

## Скорость и сборка снимка

TestClient, один процесс, тело ответа получено полностью. Раньше первый запрос KPI занимал 16 107 мс, топ запросов — 3 595 мс, причины — 512 мс, пробелы каталога — 4 278 мс. Теперь сводки сохраняются в SQLite при подготовке данных. При открытии готового чужого снимка без сводок консоль строит их до первого запроса. На отдельной чистой копии E1 запуск с загрузкой движка занял 61,32 с, затем максимум из 64 проверенных чтений составил 116,2 мс. Изменение истории или публикация нового повтора сбрасывает сводки.

На подготовленном снимке в серии из 111 последовательных запросов p95 составил 34,1 мс, максимум — 60,5 мс. Параллельная загрузка пяти API вкладки e-com заняла 36,8 мс, вкладки продукта — 42,0 мс. В отдельной серии из 55 чтений максимум — 60,4 мс. Открыты инспекторы запросов-доказательств, файлы для пяти ролей, журнал приоритетов и экспорт правил. Для источников и расходов консоль переиспользует суммы до изменения SQLite, включая запись из второго соединения. Статистика приоритетов за сутки читается по индексу живых поисков.

Для сборки ведущим в корне репозитория при установленном `KZ_DATA_DIR` применяются команды ниже.

```sh
P=/home/bb/kuznitsa-softline/.venv/bin/python
"$P" scripts/seed_priorities.py --dry-run
"$P" scripts/seed_priorities.py
```

Скрипт создаёт три выключенных правила, аудит фиксирует три операции от `seed`. Повторный запуск добавляет ноль записей, включая случай, когда менеджер уже включил пример. Для госзаказчиков выбран раздел корпоративных антивирусов с признаком отечественного ПО. Для акции срок — 31.12.2026. В примере ограничения вендора выбран Kaspersky, максимум две карточки в первой пятёрке в пределах доступных замен того же уровня.

INS-14 остаётся у потока A. В проверенной вершине нового слияния движка за ход 6 нет.

## Метрика · достижение целей

`sniff(path)` возвращает `kind="metrika_goals"` для дневных достижений. Проверены две формы CSV со служебной шапкой — три цели в колонках и название цели в каждой строке. Итоги, проценты конверсии, повторы и повреждённые значения исключены из сумм. При отсутствии событий образец дал 18 корзин, 5 заказов и 3 заявки за два дня. После импорта журнала с одним заказом в первый день и наблюдаемым нулём во второй в воронке остался один заказ. Строка сверки в `history_report.json` и на вкладке «Данные» показывает 5 / 1 (Δ +4) и два дня расхождений. Дневной источник каждого этапа доступен в `kpi.funnel_daily` и в файле менеджера e-com. Поисков, выручки и фиктивных сессий импорт агрегатов не добавляет. Сигнатура `sniff(path)` сохранена. Маршрутизация `metrika_goals` в команде `day` передана D.

Полная приёмка с отдельным временным каталогом pytest — **290 тестов прошли за 4 мин 44 с**. У TestClient осталось предупреждение Starlette о версии транспорта.

## Ход 7 · показ акции RuBackup

**Для C и Neon‑3, текст ведущего дословно**

> Выбираю профиль «Гость» и ввожу «резервное копирование». На первом месте «Кибер Бэкап Стандартный». Включаю правило «Акция на резервное копирование до 31.12» и повторяю запрос. Теперь первым идёт «RuBackup Стандарт», а «RuBackup Enterprise» поднялся с шестого места на третье. Доля RuBackup в первой пятёрке выросла с 20 до 40 %. Обе редакции помечены «Акция». Выключаю правило — первая пятёрка возвращается к исходному порядку.

| Место у гостя | Было · выключено | Стало · включено |
|---:|---|---|
| 1 | Кибер Бэкап Стандартный | RuBackup Стандарт |
| 2 | RuBackup Стандарт | Кибер Бэкап Стандартный |
| 3 | Handy Backup Professional | RuBackup Enterprise |
| 4 | Кибер Бэкап Расширенный | Handy Backup Professional |
| 5 | Кибер Бэкап Для виртуальных хостов | Кибер Бэкап Расширенный |

**Для C.** В трёх фазах маршрута выбрать правило по ID `seed-backup-promo`. Для витрины задать `q=резервное копирование`, `profile_id=guest`, `mode=fast`. Для кнопки предпросмотра отправить `queries: ['резервное копирование']`, `limit: 1`. В черновике указать `scope: {...rule.scope, profiles: ['guest']}` и `enabled: !rule.enabled`. Это выбирает гостя даже при наличии в истории других профилей. Если ведущий уже включил правило, **левая колонка показывает акцию, правая — результат выключения**. Ожидаемая подпись — «Сдвинуто позиций · 5». Для второго кадра с `gov_clinic` меняются три места: «RuBackup Enterprise» поднимается с четвёртого на второе, «Кибер Бэкап Для виртуальных хостов» и «Handy Backup Professional» смещаются на третье и четвёртое.

Проверено на `main` от `3b76e01` после `build-mock` и `build-index` в отдельном каталоге — 23 587 предложений, 654 карточки. Раньше акция давала одинаковую прибавку всему разделу. Теперь прибавку и метку получают только карточки семейства `rubackup` в разделе `backup_recovery`. Движение происходит внутри одного уровня соответствия. Порядок проверен через `Engine.preview`, служебный предпросмотр и обычный поиск до включения, после включения и после выключения. На свежем журнале первый запуск `scripts/seed_priorities.py` создал три выключенных правила, второй добавил ноль. Если используется журнал с прежним примером, в редакторе акции нужно выбрать линейку RuBackup: скрипт сохраняет существующие настройки менеджера.

Полный прогон `pytest -q` — 334 теста прошли за 6 мин 38 с. Регрессионный тест проверяет обе пятёрки, метки акции, уровни соответствия и восстановление порядка после выключения.

## Ход 7 · API Метрики и чат поддержки

На контрольных JSON-страницах `/stat/v1/data` две страницы по две строки дали три уникальные внешние фразы, одно пересечение и 15 визитов. Перестановка файлов и повторная загрузка сохраняют итог. В отдельном отчёте по URL из 13 просмотров на внутренний запрос «backup pro» пришлось 10. Остальные три просмотра относятся к карточке. В `history_report.json` видны измерения, период, имена страниц, единицы показателей, полнота и признак выборки. Поисковые сессии из агрегатов не создаются.

В контрольном CSV чата импорт принял семь обращений трёх клиентов и отклонил строку с неверной датой. Один вопрос совпал со статьёй FAQ, шесть остались для проверки редактором. Обе вкладки показывают темы, товары и вопросы. Агент проверил поиском названия и коды, по которым обратились хотя бы два клиента. На примере отсутствующего товара появилась задача `add_product`, на старом коде существующего семейства — `fix_card`. В каждой есть вопросы покупателей и ссылка на трассу. Для товара, уже найденного в первой пятёрке, задача не появилась. Денежный эффект по переписке без связанных заказов неизвестен.

**Для D.** Из `kuznitsa.ingest.history.sniff(path)["kind"]` передавать `metrika_api` и `support_chat` в `ingest_files(engine, ordered, mapping=...)`. Страницы одного отчёта можно передать одной пачкой. Каждому входному файлу соответствует квитанция, в сводке публикуется весь отчёт. **Для C.** Вкладки уже используют `GET /api/admin/support`.

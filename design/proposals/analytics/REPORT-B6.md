## Допродажи

Базовые правила читаются из YAML. SQLite хранит изменённые поля, новые правила, состояние и журнал «кто / когда / до / после». Новая редакция базы и изменения магазина меняют версию активного набора. Предпросмотр работает на запросе без публикации. При наличии модуля A черновик проходит через изолированную копию подборщика, при его отсутствии API показывает кандидата по основной выдаче. В примере «офис» из двух основных карточек получается одна рекомендация с причиной. Примеры всех семи ответов в `docs/admin_examples/upsell-*.json` сняты через TestClient на отдельном проверочном журнале.

Счётчики руководителя относятся к событиям витрины. Пара «ищут → берут» засчитывается при добавлении карточки допродажи в корзину. Пока покупатели не взаимодействовали с блоком, показы, клики и корзины равны нулю. Синтетическая история поиска их не пополняет.

**Для A.** `version, rules = kuznitsa.analytics.upsell_rules.active_rules(journal)` возвращает полный включённый набор с редакциями менеджера. Включите `rule_id` в карточку основной ленты и в рекомендацию `crosssell`.

**Для C.** `GET /api/admin/upsell/analytics` возвращает `totals`, `by_rule`, `best_pairs` с фразой, названием карточки и счётчиками. Для событий передавайте `type=impression|click|cart`, `search_id`, `card_id`, `payload={kind:"upsell",rule_id:card.rule_id}`. Для отдельного блока — `kind:"crosssell"`.

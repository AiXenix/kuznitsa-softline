## 29.2. Уточнение по смыслу: второй вопрос категоризатору (главное в ходе)

**Когда.** Только в умном режиме, после быстрого разбора, если выполнено хотя бы одно условие:

- остались значимые слова, которые разбор не объяснил («для хоума», «маме на ноут», «для серверов»);
- вид запроса — `vendor`, `category` или `broad`, и у найденного вендора или раздела в каталоге не меньше трёх продаваемых линеек с разными назначениями;
- распознана линейка, которой нет в продаже.

**Что спрашиваем.** Один вызов Decisions с двумя вопросами:

- `audience` — для кого и где. Закрытый список: `home` (дом, семья, личное), `micro_office` (1–10 мест), `business` (компания), `enterprise`, `gov`, `edu`, `server`, `mobile`, `industrial`, `none`.
- `line` — какая линейка из каталога. До 8 кандидатов: продаваемые линейки найденного вендора или раздела, с подписью «для кого» из базы знаний; плюс `none`.

Порог 0,55. Кэш по нормализованному запросу. Предел 600 мс, затем быстрый результат. Шаг трассы `refine`: вопрос, варианты, выбор, вероятность, цена.

**Что меняется в выдаче.**

- `audience` — снимаемая метка «Понято: для дома». Она переставляет и отбирает линейки по назначению: `home` и `micro_office` → малые редакции, `server` → серверные, `mobile` → мобильные.
- `line` — фильтр по линейке. Если выбрана линейка без продаж — правило 29.3.

В `understood` добавляется `refined: {"audience", "line", "source": "jev|dict", "probability"}`.

**Быстрый режим** понимает то же через словарь, без категоризатора. Neon‑4 добавляет в базу знаний:

- аудитории: хоум, домик, домашний, для дома, для семьи, маме, папе, ребёнку, личный, себе;
- платформы: сервер, андроид, айфон, мак, линукс, ноут, телефон;
- подпись «для кого» у линеек.

**Цель.** Новый набор проб «аудитория и платформа» (29.8): fast ≥ 70 %, smart ≥ 90 %; smart должен быть заметно лучше fast, на dev не хуже.

## 29.3. Пустой выдачи на понятный запрос не бывает

Если запрос понят — вендор, линейка, раздел, аудитория, — а товара нет в продаже, ответ состоит из трёх частей:

1. **Честная строка:** что именно не продаётся и почему. Например, «Домашних лицензий Kaspersky в магазине нет — магазин продаёт лицензии для организаций».
2. **Ближайшие продаваемые варианты** (блок `analogs`): связь в базе знаний, затем младшая бизнес-линейка того же вендора, затем тот же раздел.
3. **Ссылка на ответ из FAQ,** если он есть. Например: можно ли ставить домашнюю лицензию в офис.

`zero_reason` остаётся для аналитики. Покупатель видит не пустой экран, а ответ.

## 29.4. Система, а не вендор

Бывает, что вендор из запроса не продаёт товары раздела из запроса: «резервное копирование 1с», «бэкап постгреса», «антивирус для 1с-сервера», «мониторинг exchange». Тогда вендор — это система, которую защищают или обслуживают. Фильтр по вендору снимается, остаётся раздел. Выше идут товары, у которых в базе знаний или в `attrs` указана совместимость с этой системой. Метка — «Для 1С».

## 29.6. Вид `/flows`

Схемы должны выглядеть как схемы для жюри:

- подписи узлов не обрезаются, а переносятся;
- ветви разведены, подписи стрелок не наезжают друг на друга;
- у каждого узла — время шага, p50 / p95;
- легенда типов узлов;
- переключатель fast / smart.

Печать — по одной схеме на страницу.

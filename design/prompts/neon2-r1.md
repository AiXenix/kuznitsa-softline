**Шаг 4. Проверочные запросы** → `eval/queries.dev.jsonl` (не меньше 300 строк) и `eval/queries.holdout.jsonl` (не меньше 150, без
повторов dev). Одна строка — один JSON‑объект:

    {"id":"dev-0001","q":"каспер продление на 30 компов","scenario":"renewal_by_quantity","profile":"smb_trade","category_ctx":null,
     "expect":"Продление Kaspersky для бизнеса, диапазон 25–49 узлов; не новые лицензии и не домашние продукты",
     "assert":{"intent":"renewal","vendor":"Kaspersky","action":"renewal","qty":30,"metric":"device",
               "top5_any":["Kaspersky Endpoint Security","Kaspersky Small Office Security"],
               "must_not":["Kaspersky Standard","Kaspersky Premium"],"zero_ok":false}}

`scenario` — id сценария из карт (первого потока или твоей); `profile` — id профиля из шага 1 (или `guest`); `expect` — человеческое
описание правильной выдачи. Ключи `assert` (указывай только те, что уверенно следуют из запроса):
- `intent` — один из закрытого списка: `sku`, `product`, `vendor`, `category`, `task`, `role_kit`, `industry`, `analog`, `compliance`,
  `renewal`, `license_ops`, `spec_list`, `compare`, `question`, `broad`, `out_of_catalog`, `off_topic`, `account`, `service`, `promo`
  (определения — `SPEC.md`, раздел 8.5);
- `vendor` — название вендора; `family_any` — названия продуктов, любой из которых должен быть понят как предмет запроса;
- `action` — `new|renewal|upgrade|crossgrade|addon|support`; `model` — `subscription|perpetual`; `qty` — число;
  `metric` — `device|user|server|core|cpu|vm|mailbox`; `term_months` — число;
  `platform` — `windows|windows_server|linux|macos|android|ios|astra|alt|redos`; `audience` — `business|gov|edu|home`;
  `registry` — true/false; `certs` — список из `fstec|fsb`; `price_max` — число в рублях; `category` — id из `kb/categories.yaml`;
- `top5_any` — названия продуктов: хотя бы одно должно встретиться в заголовках первых пяти карточек (подстрока без учёта регистра);
  `top1_any` — то же для первой карточки; `must_not` — подстроки, которых не должно быть в заголовках первых пяти карточек;
- `block_any` — ожидаемые блоки ответа: `products|kit|analogs|answer|spec|compare|not_in_catalog|categories|clarify|my_licenses`;
- `zero_ok` — true, если честный ответ «в каталоге нет»; `corrected_to` — исправленный текст запроса (опечатка, раскладка);
- `exclude_vendor` — вендор, который пользователь исключил («не касперский»).
Для списков‑спецификаций в `q` используй `\n` между позициями и добавь `"lines": N` в `assert`.
Покрой все сценарии обеих карт и все виды языковых искажений (опечатки, неверная раскладка в обе стороны, транслит, жаргон,
сокращения, слитное написание, двойники букв в артикулах). Не меньше 40 строк — на персонализацию (один запрос, разные профили,

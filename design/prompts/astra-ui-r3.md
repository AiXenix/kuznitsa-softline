C2 принят, слит и развёрнут на стенде. Общая ветка `main` = `2d0c3b8`; твоя копия `/home/bb/kuznitsa-softline-ui` (ветка `ui`)
уже на ней. Правила прежние: зона записи `web/**`, `kuznitsa/pages.py`, `tests/web/**`, `docs/UI.md`, `design/proposals/ui/**`;
без коммитов; без внешних шрифтов, CDN, сборщиков и графических библиотек; числа — только из API.

Идёт третий ход — прочитай `design/spec-addendum-v0.4.md`. Параллельно с тобой работают: поток A (движок: новые поля ответа
поиска из 26.3, запросы показа, подсказки), поток B (служебный API из 26.6, правдоподобная история, скорость чтения), поток D
(импорт каталога, 26.5 — сводка появится в `GET /api/admin/ingest` полем `catalog`). Правило то же, что в C2b: поле есть —
показываем; поля ещё нет — работаем на том, что отдаёт твоя копия сейчас, без заглушек и выдуманных чисел. Новые поля
закладывай по тексту дополнения и закрепляй тестами на образцах в `tests/web/`.

Хакатон оценивают по показу, поэтому я прошёл стенд глазами жюри: кадр 1366 × 768, затем телефон 390 × 844. Ошибок
JavaScript нет ни на одной странице. Общий вид, строка «Понято так», трасса из 15 шагов, сравнение и панель показа —
хорошие, их не ломаем. Ниже — всё, что мешает показу.

## Как проверять глазами

На сервере есть headless Chrome через `bb browser-automation` — тот же, которым смотрел я:

```bash
bb browser-automation open --backend local --headless --json      # вернёт идентификатор сеанса
bb browser-automation run <сеанс> --script-file <файл.js> --timeout 110s --json
bb browser-automation close <сеанс>
```

Сценарий похож на Puppeteer: `const p = await browser.getPage("main")`, дальше `p.setViewport`, `p.goto`, `p.type`, `p.click`,
`p.keyboard.press`, `p.evaluate`, `p.shot({type: "jpeg", maxEdge: 1366, quality: 45})`. За один запуск — до четырёх снимков,
только JPEG, вместе до 500 КБ; снимается видимая область, для длинной страницы увеличивай высоту окна. Пути снимков приходят
в `images[].path`. Мои сценарии лежат в `/home/bb/kuznitsa-softline-ops/browser/` (`q1_store.js` … `q4_admin2.js`) — возьми их
за образец и замени адрес на свою копию `http://127.0.0.1:8197`. Точный синтаксис — `bb browser-automation --help`. Сеанс
в конце закрой. Стенд на `127.0.0.1:8097` можно только читать.

Умный режим в своей копии включается через общий шлюз категоризатора (26.2): `KZ_JEV_URL=http://127.0.0.1:8098/decisions`
и `OPENROUTER_API_KEY=gateway`. Дневной предел общий на все потоки — не гоняй его циклами.

## Слова, которые видит жюри

- Режим `naive` всюду называется **«Обычный поиск по словам»** (в переключателе — «Обычный»), а не «Наивный» и не «прежний
  поиск магазина»: мы не знаем, как устроен настоящий поиск магазина, и не утверждаем, что воспроизводим его. Это модель
  типового поиска по совпадению слов. `fast` — «Быстрый», `smart` — «Умный». В сравнении столбцы подписаны «Обычный поиск
  по словам» и «Кузница · умный режим».
- Ни один служебный идентификатор не попадает на экран: `task_project_trackers`, `llm_gen_ai`, `red_hat`, `role_kit`,
  имена файлов наборов, значения `source`. Сделай одну функцию подписи (вид, идентификатор) → название из `/api/meta`
  (сценарии, категории, вендоры, сегменты, профили); если названия нет — очеловеченный идентификатор (пробелы вместо
  подчёркиваний, первая буква заглавная) и запись в отчёт, какого названия не хватило.
- Деньги не рвутся переносом: неразрывные пробелы внутри числа и перед «₽», `white-space: nowrap`. Суммы меньше рубля —
  две значащие цифры («≈ 0,0095 ₽»), а рядом понятная мера: «9,5 ₽ за 1 000 запросов». Доллары нигде не показываем.

## 1. Витрина `/`

1. **Карточка товара.** Сейчас название варианта справа обрезается («Kaspersky Endpoint Security для биз…»), заголовок
   слева переносится на две строки при свободном месте, расчёт рвётся как «= 31 / 500 ₽». Нужно: заголовок — на всю ширину
   первой строки; под ним — условия лицензии метками («продление», «12 мес», «25–49 узлов», «электронная поставка»), без
   повтора названия семейства в названии варианта; расчёт «30 × 1 050 ₽ = 31 500 ₽» — в одну строку, перенос допустим
   только перед «=»; у обрезанного текста — полная подсказка в `title`.
2. **Недоступная карточка.** У карточки без кнопки «В корзину» сейчас нет ни объяснения, ни действия. Показывай состояние
   («Нет в продаже», «Цена по запросу») и кнопку «Запросить счёт» — она открывает ту же заявку, что блок `lead`, с уже
   подставленной карточкой и количеством из запроса. Порядок карточек не меняй — это дело движка.
3. **«Почему здесь».** Первая причина из `score.why` видна сразу, одной строкой под заголовком; остальные — по раскрытию.
   Если пришёл `score.tier_label` — метка уровня соответствия рядом с заголовком («Точное соответствие», «Близкий вариант»).
4. **Клиент виден без клика.** Мелкий переключатель «О профиле» наезжает на рамку поиска, а контекст клиента — одно из
   требований задачи («один и тот же запрос от разных людей даёт разную выдачу»). Под строкой поиска — постоянная строка
   клиента: короткое имя (`profile.short`, иначе название), сегмент (`profile.segment_title`), число рабочих мест, отрасль
   и ближайшее истечение лицензии из `/api/profile/{id}` («истекает через 24 дня: …»). По клику — прежняя полная
   карточка профиля. У гостя — «Гость: без истории, персонализация выключена».
5. **Плитки итога.** В умном режиме при ответах из кэша плитки показывают «0 Вызовы модели · 0 ₽» — жюри решит, что модель
   не работала. Показывай по `cost`: «Категоризатор: 2 ответа, оба из кэша» и «Цена: 0 ₽»; если пришло `cost.saved_rub`
   (поток A добавляет: сколько стоили бы ответы без кэша) — «без кэша ≈ 0,01 ₽». Когда шаг категоризатора пропущен —
   «Категоризатор не понадобился: решено правилами». В шагах трассы цена — в рублях; если рублей у шага нет, цену шага
   не показываем.
6. **Панель трассы.** Занимает треть ширины, имеет собственную прокрутку и при высоте 768 показывает три шага из 15. Сделай
   сжатый вид: 15 строк по одной на шаг (номер, название, итог шага в 3–5 словах, время), все помещаются в кадр 768 без
   прокрутки; шаги, которые что-то изменили, выделены, пропущенные приглушены, шаги с моделью помечены; подробности шага —
   по клику. Ширина панели не больше 340 px, сворачивается кнопкой, выбор запоминается.
7. **Развёрнутая трасса.** У шага 11 статус переносится под метку и ломает строку; ссылка «Открыть разбор запроса →» внизу
   обрезается краем окна.
8. **Сравнение режимов.** По умолчанию пара «Обычный поиск по словам ↔ Кузница · умный режим»; переключатель пары добавляет
   «Быстрый ↔ Умный». В шапке каждого столбца — число карточек, время ответа и цена запроса. Карточки, которых нет во
   втором столбце, отмечены; общие — с позицией в другом столбце («у обычного поиска — 7‑я»).
9. **Подсказки под строкой поиска.** Сейчас только группы «Продукты» и «Вендоры». Поток A добавляет группы (форма ответа
   прежняя: `groups: [{type, title, items: [{text, kind, meta}]}]`, у элемента появятся необязательные `hint` — серая
   подпись и `q` — запрос, который выполнить по клику). Отрисовывай группы любого типа по их `title`; для известных типов —
   свой значок и порядок: `corrections` («Возможно, вы искали»), `queries` («Запросы»), `licenses` («Ваши лицензии»),
   `products`, `categories`, `vendors`. `corrected` — отдельной строкой «Исправлено: …». Совпавшее начало выделяй, когда
   текст подсказки его содержит. Управление с клавиатуры: ↑ ↓ Enter Esc. Запрос подсказок — с задержкой 120–150 мс и
   отменой предыдущего.
10. **Пустая выдача по причине.** `understood.zero_reason` (26.3) задаёт вид экрана, когда товаров нет:
    `off_topic` — вежливый отказ и разделы каталога; `unknown_term` — «не узнали слово „…“», подсказки и заявка;
    `not_in_catalog` — «в каталоге нет, вот аналоги» и кнопка «Сообщить о появлении»; `vendor_left` — российские аналоги
    первыми; `filters_too_strict` — кнопки «снять условие» из `relax_hints`, каждая сразу повторяет поиск;
    `qty_out_of_range` — ближайшие ступени количества; `no_available_offer` — «Запросить счёт». Значения нет — работает
    нынешний вид. Заявка никогда не остаётся единственным содержимым экрана, если в ответе есть ещё блоки.
11. **Телефон 390 px.** Верхнее меню не помещается («О р…»), списки профиля и режима обрезаны. Меню — прокручиваемой
    строкой или кнопкой, списки — во всю ширину друг под другом; панель трассы — под выдачей, свёрнута.

## 2. Консоль `/admin`

1. **Загрузка.** Замер на стенде (45 000 поисков истории): `/kpi` — 5,7 с и 136 КБ, `/queries?kind=…` — 1,6–2,4 с каждый,
   `/failures` — 1,5 с, `/gaps` — 2,9 с и 189 КБ; вкладки `#ecom` и `#product` через 2,5 с всё ещё показывают
   «Загрузка…». Поток B ускоряет API до 300 мс, но интерфейс не должен от этого зависеть: запрашиваются только данные
   открытой вкладки; каждый блок рисуется сам, как только пришёл его ответ; вместо слова «Загрузка…» — заготовка формы
   блока; один и тот же адрес не запрашивается дважды (общий запрос для блоков), ответы хранятся до кнопки «Обновить»
   или до действия, меняющего данные; ожидание дольше 15 с — сообщение с кнопкой «Повторить».
2. **Шапка.** Сейчас сырая строка «2026-08-24 — 2026-11-21 / api · 49 / compare · 2 / eval · 1 020 / history · 45 000 /
   replay · 3 000 / ui · 6». Нужно: «Журнал: 24.08 — 21.11.2026 · история магазина 45 000 · живые запросы 57 · служебные
   прогоны 4 020»; состав по источникам — в подсказке и на вкладке «Журнал».
3. **До / после.** Строим по `kpi.pairs` (26.6): подпись, «было → стало», разница в процентных пунктах, рублях или
   миллисекундах по `unit`; цвет разницы — по `better`; под парой мелко `n_before`, `n_after` и `note`. Воронка — по
   `kpi.funnel`. Пока полей нет — нынешний блок на `kpi.comparison`.
4. **Графики по дням.** На последнем дне всплеск поисков и провал доли пустых: в ряд попали живые и служебные запросы.
   Ряд строится по истории магазина; неполный последний день не рисуется или помечен пунктиром; у графика есть легенда
   и подписи осей.
5. **Экономика ИИ.** «0,00954284 ₽» — по правилу для малых сумм. Новые поля `/cost` (26.6): сколько вызовов ушло наружу
   (`sent`) и сколько взято из кэша (`cached`), цена запроса по режимам, прогноз на месяц и цена 100 000 запросов —
   одной строкой‑выводом: «100 000 умных запросов ≈ … ₽».
6. **Качество на проверочном наборе.** Вместо `651bd7fb914241888bfffa4d1a57893a.jsonl` — «Проверочный набор, 310 запросов»
   (число из ответа), вместо идентификаторов сценариев — их названия.
7. **Агент.** Заголовок первого предложения продублирован крупной строкой над лентой — убрать. Примеры запросов
   в доказательствах — ссылки на разбор по собственному `search_id` (26.6), так же в «Причинах неудач» и «Пробелах».
8. **Журнал `#log`.** `GET /queries?kind=recent&limit=50` (26.6): время, запрос, профиль и сегмент, режим, сценарий, число
   карточек, время ответа, цена, причина пустой выдачи; строка ведёт в разбор. Переключатель «обновлять каждые 5 с» —
   на показе запрос, введённый на витрине, должен появиться здесь на глазах. До появления `recent` — нынешний вид.
9. **Импорт каталога.** Новый блок на вкладках «Контент‑менеджер» и «Журнал» по `ingest.catalog` (форма — 26.5,
   `import_report.json`): файлы и дата, строк → предложений, отклонено, дубли; доли распознавания вендора, семейства,
   редакции, условий лицензии и категории — полосами; сколько записей добавлено в базу знаний автоматически; таблица
   замечаний к данным (`issues`: название, число, пример строки); нераспознанные вендоры и семейства. `catalog = null` —
   блок с пояснением, какой командой загрузить каталог.
10. **Разбор запроса `/inspect`.** У каждого шага печатается пустой блок `{}` — пустое не показываем; данные шага —
    строками «название: значение», исходный JSON — по раскрытию. Поле «Ключ доступа» стоит посреди шапки — в правый
    угол, как в консоли.

## 3. Режим показа и страница «О решении»

- Пройди оба маршрута `/?show=1` в кадре 1366 × 768: на каждом шаге главное видно без прокрутки, панель показа ничего не
  закрывает, текст подсказки ведущему читается, стрелки ← → на клавиатуре листают шаги. Тексты шагов не обещают чисел,
  которых нет на экране. Запросы шагов движок поправит в этом ходе (поток A) — не подгоняй под нынешние ответы.
- `/about` отвечает на три вопроса из условий хакатона: что происходит с запросом по шагам; какие сторонние библиотеки,
  модели и сервисы использованы (с лицензиями; версии и модели — из `/health` и `/api/meta`); сколько стоит запрос
  (из `/api/admin/cost`). Двадцать видов поиска — с примером запроса, который открывает витрину.

## Приёмка

- `pytest -q` и `node --check` для всех модулей проходят. Новые проверки в `tests/web/`: функция подписей не пропускает
  идентификаторы со знаком подчёркивания; денежный формат (неразрывные пробелы, малые суммы); отрисовка `kpi.pairs`,
  `kpi.funnel`, `queries?kind=recent`, `ingest.catalog`, всех значений `zero_reason` и групп подсказок — на образцах;
  отсутствие каждого нового поля не ломает страницу.
- Снимки headless‑браузера в кадре 1366 × 768: `/?q=антивирус на 30 пк&profile=smb_trade&mode=smart` (карточки, строка
  клиента, 15 шагов трассы без прокрутки), тот же запрос с `compare=modes`, развёрнутая трасса, подсказки для «касп»,
  `/admin#head`, `#ecom`, `#product`, `#content`, `#agent`, `#log`, `/inspect/{id}` свежего запроса; в кадре 390 × 844 —
  витрина с тем же запросом. В отчёте — что проверено и что увидел.
- `docs/UI.md` дополнен. Отчёт — `design/proposals/ui/REPORT-C3.md`: что сделано; каких полей на момент сдачи не было
  в твоей копии (по потокам A, B, D); какие названия не нашлись в `/api/meta`; что в данных выглядит неправдоподобно.

# D2 · Категоризатор на импорте и самопроверка поиска на чужом каталоге

D1 принят и зафиксирован в ветке `data` (коммит `ea40eb9`); в `main` он войдёт при общем слиянии в конце хода. Продолжай
в той же копии и ветке. Твой `integration.patch` передан потоку A как образец для 26.4–26.5: он делает эти вставки в своей
зоне, расхождения сведу при слиянии. Зона записи и правила прежние (`design/spec-addendum-v0.4.md`, 26.1): чужие файлы не
правятся, вставки в них — дословно в отчёте, коммитов нет.

Закрытые списки (категории, задачи, роли, отрасли) бери через загрузчик базы знаний, а не чтением файлов напрямую: в конце
хода к ним добавятся файлы `kb/*_r3.yaml` (задач станет 336 вместо 216, ролей и отраслей — примерно вдвое больше).

## Зачем

26 ноября организаторы дадут настоящий каталог. База знаний знает 481 семейство, у магазина их тысячи — большинство строк
окажутся «неизвестными». Сейчас такая линейка получает автозапись: вендор, название, категория магазина. Её найдут по
названию и артикулу, но не найдут по классу ПО («антивирус»), по задаче («чем чертить в dwg»), по роли, отрасли и как
аналог: эти виды поиска держатся на признаках из базы знаний. Импорт должен сам раскладывать неизвестные товары по нашим
закрытым спискам. Это ровно та работа, для которой в проекте есть категоризатор (Jev 1.13: выбор из закрытого списка
с вероятностями), — и хороший кадр для жюри: «загрузили ваш каталог, категоризатор разложил его по полкам за … ₽».

## Задача 1. Раскладка неизвестных товаров по закрытым спискам

Три режима: `--ai off` (как в D1), `--ai embed` (локальные эмбеддинги и правила, без сети) и `--ai jev` (эмбеддинги отбирают
кандидатов, категоризатор выбирает). По умолчанию `embed`.

1. **Категория магазина → наша листовая категория.** Для каждой категории магазина (полный путь) — 6–8 кандидатов из наших
   134 категорий: близость эмбеддингов и совпадение слов по `title` и синонимам, плюс вариант «ничего не подходит».
   В режиме `jev` — один вопрос на категорию магазина (не на строку): в состоянии путь категории, 5–10 названий товаров из
   неё, вендоры; у каждого кандидата описание. Решение принимается при вероятности не ниже 0,55 (как в движке); иначе
   остаётся автокатегория, привязанная к нашему разделу‑родителю, если раздел определён уверенно.
2. **Семейство без категории.** Категории в файле нет или она общая («Программное обеспечение», «Прочее», «Новинки») —
   тот же вопрос по названию семейства, вендору и описанию.
3. **Признаки семейства из закрытых списков.** Задачи (`use_cases`), роли (`roles`), отрасли (`industries`): кандидаты —
   эмбеддингами по фразам и названиям из базы знаний, подтверждение — категоризатором (в режиме `embed` принимаются только
   самые близкие, с пометкой низкой уверенности). Платформы, способ развёртывания, вид поставки — только правилами из
   текста строки. **Реестр, сертификаты ФСТЭК и ФСБ — только из явных данных файла**: модель их не угадывает никогда.
4. **Аналоги.** Для неизвестной линейки — до пяти ближайших семейств той же категории (сначала из базы знаний); у ушедшего
   вендора — российские замены. Это предложения с уверенностью, а не утверждения.
5. **Запись.** Всё попадает в `kb_auto.yaml` (26.4, поля по `kb/SCHEMA.md`). Каждое решение — строкой в
   `<данные>/import_ai.jsonl`: объект, вопрос, варианты, выбор, вероятность, принято или нет, источник (`rule`, `embed`,
   `jev`), цена. Запись основной базы знаний автозаписью не заменяется.
6. **Деньги и отказ.** `--ai-budget-usd` (по умолчанию 0,5); ответы кэшируются, повторный импорт того же файла не платит;
   два параллельных вызова; при исчерпании бюджета, ошибке сети или ответе 429 — понижение до `embed` с пометкой в отчёте.
   `--dry-run` печатает прогноз: сколько вопросов будет задано и сколько это стоит. Число вопросов растёт с числом
   неизвестных категорий и линеек, а не строк. Офлайн‑часть по‑прежнему укладывает 100 000 строк в минуту.
7. **Отчёт.** В `import_report.json` — раздел `ai`: `{mode, questions, sent, cached, usd, accepted, rejected,
   by_kind: {category, use_cases, roles, industries, analogs}}` и до десяти примеров решений с вероятностями: принятых
   и отклонённых. Раздел предназначен для консоли контент‑менеджера (очередь на проверку) — подключим на следующем ходу.

Клиент категоризатора, кэш и эмбеддер уже есть в движке — пользуйся ими через один тонкий переходник в `kuznitsa/ingest/`
(поток A сейчас меняет категоризатор, поэтому зависимость должна быть в одном месте). Живые вызовы — только через шлюз
(26.2); на весь ход тебе хватит 0,3 $. Тесты в сеть не ходят: подменный транспорт.

Проверь на деле, что движок использует признаки автозаписей: после импорта образца запрос‑задача и запрос «аналог …»
находят выдуманную линейку. Если движок читает задачи только из `kb/use_cases.yaml`, а не из записи семейства, — опиши
нужную вставку дословно в отчёте.

## Задача 2. Самопроверка поиска на импортированном каталоге

```bash
python -m kuznitsa.ingest.cli selfcheck [--n 300] [--mode fast|smart] [--seed 7] [--report selfcheck.json]
```

Берёт случайные предложения текущего каталога данных (поровну по вендорам и категориям, с фиксированным зерном) и по
каждому строит запросы‑пробы: точное название; название без служебных слов; артикул; вендор и семейство; название
с опечаткой; в неверной раскладке; кириллицей по звучанию; с количеством из ступени («… на 30 пк»); класс ПО и вендор.
Проверка — семейство (а где проба называет редакцию — и редакция) в первой тройке и в первой пятёрке. Отчёт: доли по видам
проб, отдельно для известных базе знаний и неизвестных линеек; время ответа p50 и p95; до десяти худших примеров на вид
пробы. Работает только через открытый вход движка, код движка не правится; находки по движку — списком для потока A.

Это число покажем жюри: «на вашем каталоге, загруженном час назад: точное название — … %, опечатка — … %».

## Задача 3. Образец «длинный хвост»

`docs/ingest_examples/longtail.*`: 250–400 строк из 60–80 выдуманных линеек вымышленных вендоров по всей таксономии.
Категории магазина названы не так, как наши («Антивирусы и защита / Для бизнеса», «САПР», «Офис и документы», «Прочее»);
у части строк категории нет. Эталон: наша категория каждой линейки, для трети — задачи и роли. На нём измеряется точность
раскладки: `embed` — в тестах (эмбеддинги локальные), `jev` — одним живым прогоном через шлюз, с ценой и временем.

## Приёмка

- Полный `pytest -q` проходит. Быстрый dev не ниже 237/310. Круговой импорт демокаталога по‑прежнему совпадает по всем полям.
- На образце «длинный хвост»: верная категория в режиме `embed` не ниже 70 %, в режиме `jev` не ниже 88 %; ни одной записи
  с реестром или сертификатом, которых нет в файле.
- Самопроверка выполнена на трёх каталогах: демо, импорт `price.xlsx`, импорт «длинного хвоста» — числа в отчёте.
- `docs/INGEST.md` дополнен разделом «День данных»: команды по порядку от файлов организаторов до витрины, сколько каждая
  идёт, что смотреть в отчётах, что делать, если распознано мало.
- Отчёт — `design/proposals/data/REPORT-D2.md`: что сделано; точность и цена раскладки; результаты самопроверки; находки
  и вставки для потоков A и B.

## Задача 1. Витринные названия → `kb/overrides/families.yaml`

Сейчас у 254 семейств из 481 в `name` стоят скобки с версиями, пояснениями и перечнями редакций, а названия редакций часто
повторяют название семейства. На витрине получается «МойОфис Стандартный Стандартный 2 / 3» и
«Astra Linux Special Edition (1.7 / 1.8) Усиленный (Воронеж)». Нужна запись **для каждого из 481 семейства**:

```yaml
kaspersky_kesb:
  title: Kaspersky Endpoint Security для бизнеса
  editions: {standard: Стандартный, advanced: Расширенный, total: Total}
astra_linux_se:
  title: Astra Linux Special Edition
  editions: {orel: «Орёл», voronezh: «Воронеж», smolensk: «Смоленск»}
windows_server:
  title: Microsoft Windows Server
  editions: {standard: Standard, datacenter: Datacenter}
```

Правила:
- `title` — название, как его пишут в каталоге магазина ПО для юрлиц: бренд и продукт, на том языке, на котором пишет вендор.
  Без версий, скобок, слэшей‑перечислений, «ранее …», пояснений о назначении. До 45 знаков. Цифра остаётся только там, где она
  часть имени продукта («Windows 11», «1С:Бухгалтерия 8»).
- `editions` — отображение `id редакции → название редакции` ровно для тех id, что есть у семейства в таблице. Название редакции
  не повторяет семейство. Проверка: строка `title + пробел + редакция` должна читаться как название товара
  («Kaspersky Endpoint Security для бизнеса Расширенный», «Astra Linux Special Edition «Воронеж»»). Нет редакций — ключ не пиши.
- `max_seats` и `upgrade_to` (раздел 24.4 в `SPEC.md`) — только там, где предел мест известен достоверно
  (линейки для малого бизнеса, базовые версии 1С). `upgrade_to` — id старшей линейки из таблицы.
- Порядок записей — как в таблице. Отступ 2 пробела. Значения с двоеточием, кавычками‑ёлочками в начале или решёткой бери в
  двойные кавычки.

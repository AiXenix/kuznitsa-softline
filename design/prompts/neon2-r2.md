## Задача 1. Привязать знания к настоящим семействам

В `kb/roles.yaml`, `kb/use_cases.yaml`, `kb/industries.yaml` поле `families` везде пустое, а продукты названы текстом в
`products`. Поиск по названию через словарь иногда ошибается, поэтому заполни `families` явными id:
- в каждом слоте роли и отрасли и в каждой задаче — 2–6 id в порядке рекомендации для типичного российского юрлица;
- сначала те, что продаются (`catalog: yes`); ушедшие с рынка — только если слот без них теряет смысл, и после российских;
- список `products` оставь как есть (можно дополнить). Если названного продукта в таблице нет — в `families` его не добавляй,
  а название выпиши в отчёт.
Файлы переписывай целиком и аккуратно: ни одна запись, алиас или фраза не должны пропасть.

## Задача 3. Сопутствующие товары → `kb/crosssell.yaml`

40–60 правил «с этим обычно берут» для магазина ПО для юрлиц, формат — раздел 25.6:

```yaml
- id: cs_desktop_os_office
  when: {categories: [desktop_os_ru], families: []}
  suggest:
    - {category: office_suite, families: [r7_office, myoffice_standard], reason: "На новое рабочее место вместе с ОС берут офисный пакет"}
    - {category: endpoint_security, families: [kaspersky_kesb], reason: "Антивирус, совместимый с российской ОС"}
  note: Комплектование нового рабочего места
```

Правила должны отражать реальную логику закупки: рабочее место (ОС → офис → антивирус → почта), 1С (сервер 1С → СУБД →
клиентские лицензии → резервное копирование → ЭДО и отчётность), виртуализация (гипервизор → резервное копирование →
мониторинг), защита информации (СЗИ от НСД → антивирус → СКЗИ → токены), ВКС и совместная работа, САПР (САПР → расчёты →
PDM), разработка, образование. `reason` — одна фраза для покупателя, без рекламных штампов. id категорий — из
`kb/categories.yaml`, id семейств — из таблицы.

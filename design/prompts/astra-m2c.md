# M2c — четвёртый ход, поток A: движок

M2b принят, слит и развёрнут: `main` = `{{REV}}` — в ней весь третий ход (B2, C3, D1–D2, K1–K2b); твоя рабочая копия
на этой вершине. Зона прежняя: всё, что не отдано другим потокам (26.1 и 27.2).

Сначала прочитай `design/spec-addendum-v0.5.md`: замеры на стенде (27.1), договорённости с соседями (27.3–27.8),
контрольные наборы (27.9), цели (27.10). Затем — `eval/AMENDMENTS.md`, `design/proposals/ui/REPORT-C3.md` (раздел
«Наблюдения для потоков A и B»), `design/proposals/data/REPORT-D2.md` и `design/proposals/data/integration-D2.patch`.

## Зачем

Показ — 26–27 ноября, оценка по демо. Прямые запросы движок понимает хорошо (dev 292 из 310). Слабое место, которое
я измерил: покупатель описывает себя своими словами — «чо нужно в стоматологию на 5 кресел из программ», «проги для
ветклиники», «что нужно геймдев студии на 25 человек из лицензий» — и получает общий раздел или «не по теме». Из 149
новых формулировок ролей и отраслей комплект собран в 36 (24 %), причём в умном режиме столько же, сколько в быстром:
категоризатор в выборе записи не участвует. «Поиск по профессии и отрасли» — наша визитная карточка, это главный пробел.

## P0

1. **Роль, отрасль и комплект из свободной формулировки.** Чем меряю: `design/proposals/neon4/probes-kits-r3.jsonl`,
   правило зачёта — в 27.9. Сейчас: знакомые формулировки — 123 из 125; новые — роли 22 из 101, отрасли 14 из 48. Куда
   уходят 115 промахов умного режима: выбрана не та запись — 50 (чаще общая вместо частной: `healthcare` вместо
   `dentistry_private_clinic`, `education` вместо `college_spo`, `manufacturing` вместо `machinery_engineering`,
   `pharma_biotech` вместо `pharmacy_chain`); намерение `category` — 33; `off_topic` — 16; `task` и `compliance` — по 5–6;
   единичные — `license_ops`, `product`, `analog`, `service`. Примеры: «какое по нужно в диагностическую лабораторию…» →
   `science_rnd`; «проги в рекрутинговое агентство на 10 рекрутеров» → роль `recruiter_hrbp` вместо отрасли; «программы
   в муниципальный детсад бухгалтерия и офис» → роль `accountant`, раздел; «софт аудиторской фирме на 20 человек» → раздел;
   «какие программы взять ипшнику на один ноутбук» → не по теме; «импортозамещение сапр в проектном институте на 80
   человек» → аналоги, пусто; знакомые: «по для вуза» → раздел, «инженер техподдержки» → услуги.
   Что нужно:
   - признак «просят набор для кого‑то» (что нужно; какие программы; софт, проги, по — для, в, на …; комплект, набор, стек;
     что закупить, чем оснастить, автоматизация <организации>) сильнее раздела, задачи и «не по теме», когда рядом есть
     кандидат — роль или отрасль;
   - кандидаты — не только точные слова из `aliases`: смысловая близость запроса к названию, словам и заметкам слотов
     записи (векторная модель в индексе уже есть; ролям и отраслям нужен свой маленький индекс), плюс леммы и опечатки;
   - быстрый режим берёт лучшего кандидата, если он уверенно впереди; иначе — блок `clarify` с двумя‑тремя вариантами
     («Стоматология», «Клиника», «Аптека»), а не общий раздел;
   - умный режим: категоризатор выбирает из закрытого списка — до восьми кандидатов (название и строка о записи) и вариант
     «ничего из перечисленного»; порог принятия прежний (0,55); ответ кэшируется. API решений принимает несколько вопросов
     в одном вызове — намерение и запись можно спросить вместе, без второго обращения;
   - частное важнее общего и роль внутри отрасли — по 27.3. Поле `parent` в файлах r3 пишет Neon‑4 в этом же ходе; пока
     его нет — проверяй на временной копии `kb` со своими `parent`;
   - соседние случаи не должны пострадать: «антивирус для бухгалтерии», «1с для аптеки», «сапр для машиностроения» — это
     товар или раздел с условием, а не комплект.
   Фразы с `seen: false` нельзя переносить ни в базу знаний, ни в код, ни в тесты: рост должен давать механизм. Итог
   я проверю на закрытом наборе; каталог `holdout` (он лежит в копии `-kb`) не открывай.

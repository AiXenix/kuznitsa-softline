# «Кузница Softline» — умный поиск для B2B‑магазина программного обеспечения

Общий бриф для всех участников работы. Автор — архитектор проекта (Claude Fable 5.2, родительский тред).
Бренд владельца: **AiXenix**. Личные имена нигде не используем.

## 1. Зачем это делается

Команда AiXenix участвует в хакатоне «ИИкузница», задача **«Умный поиск на сайте»**.
Полное ТЗ и данные организаторов откроются **26 ноября 2026**. До этого мы готовим собственное сильное решение на mock‑данных,
чтобы 26‑го только подменить данные и довести детали.

Дословные ответы организаторов (полный текст — `design/FAQ-hackathon.txt`):

- Магазин: «Онлайн магазин программного обеспечения, в основном для юрлиц».
- Агентность: агент работает на нескольких пользователей продукта —
  клиент находит нужный товар с первого запроса; менеджер e‑com получает рост конверсии поиска в заказ;
  продукт‑менеджер получает данные о том, что ищут клиенты; контент‑менеджер видит, каких товаров не хватает в каталоге;
  руководитель e‑com получает рост онлайн‑заказов. «Система отдаёт не только выдачу покупателю, но и вывод для бизнеса».
- Агент «разбирает запрос и понимает, что человек имел в виду. Работает с синонимами, опечатками, сленгом и аббревиатурами».
- «Учитывает контекст: категорию, сегмент, историю клиента. Один и тот же запрос от разных людей может дать разную выдачу».
- Ожидаемый результат: понимать смысл запроса; выдавать релевантное даже без точного совпадения; учитывать контекст;
  **ранжировать по релевантности, популярности и маржинальности**; **подсказывать — автодополнение, исправление опечаток,
  связанные запросы**; **анализировать неудачные поиски (что ищут и чего нет в каталоге)**; **логировать действия и показывать
  аналитику по поиску**. Аналитика — часть задачи, а не дополнение.
- Данные: «каталог товаров, поисковые запросы, данные с метрики», только mock.
- Сдача: отдельное демо; «достаточно показать, что происходит с запросом по шагам». Оценка — по демо.
- Ограничений на модели/контур/время ответа нет, но нужно показать **стоимость запроса** и перечислить модели и библиотеки.
- Бизнес‑эффект: доля запросов без результата, уходы после неудачного поиска, конверсия поиска в заказ, потеря онлайн‑заказов,
  появление аналитики по поиску там, где её нет.

Референс магазина: **https://store.softline.ru/** (ПО для юрлиц: вендор → семейство продукта → SKU‑лицензии; у SKU есть
срок, платформа, тип лицензии «новая/продление», тип клиента, диапазон количества узлов, артикул вендора, НДС, «цена по запросу»).
Материалы разведки сайта лежат в `/home/bb/kuznitsa-softline-ref/softline/` (только структура и примеры, не для копирования каталога).

## 2. Что уже есть у AiXenix (на чём стоим)

1. **Поиск спецодежды r36** (боевой, его НЕ трогаем). Сила — понимание запроса по сценариям: не только «китель повара»,
   но и поиск по профессии, отрасли, вредным факторам, сезону, комплектам и нормам выдачи, с ценой, исключениями, брендами,
   артикулами, сленгом, опечатками, неверной раскладкой. Техника: словари‑лексиконы (longest match), исправление опечаток
   по словарю каталога, **закрытые классификаторы Jev 1.13 («категоризатор») через OpenRouter Decisions API**
   (вопрос + закрытый список вариантов → вариант и вероятности; ~$0.042 за 1 млн входных токенов), BM25 по полям,
   Jev‑реранк верхнего окна, объяснение «что понял поиск», кэши, журнал запросов, правила мерчандайзинга.
   Эмбеддингов в r36 нет. Копия исходников для чтения: `/home/bb/kuznitsa-softline-ref/r36_engine/`.
2. **Универсальный гибридный движок `search_core`** (демо для произвольных каталогов): слова TF‑IDF + символьные n‑граммы +
   **локальные эмбеддинги MiniLM (ONNX, fastembed, без платных API)**, RapidFuzz, раскладка/транслит, точные артикулы.
   Копия: `/home/bb/kuznitsa-softline-ref/search_core/`.

Новый проект берёт идеи обоих, но это **отдельная кодовая база** под предметную область «программное обеспечение».

## 3. Рабочая гипотеза решения (её можно и нужно оспаривать)

Онлайн‑конвейер, каждый шаг пишет запись в трассу «как агент понял запрос»:

1. Нормализация, учитывающая ПО (`C++`, `1С:Бухгалтерия 8.3`, `office2021`, `win11`, смешение кириллицы/латиницы, артикулы вендора).
2. Точный артикул/код → сразу товар.
3. Языковой ремонт: раскладка, транслит («майкрософт»), опечатки по словарю каталога и базы знаний.
4. Извлечение сущностей словарями: вендор, семейство, редакция, версия, категория, действие с лицензией (новая/продление/апгрейд),
   модель (подписка/бессрочная), срок, количество и метрика (ПК/пользователи/ядра), платформа, поставка (электронная/коробка),
   аудитория (бизнес/гос/образование/дом), регуляторика (реестр российского ПО, ФСТЭК/ФСБ), цена, исключения.
5. Сценарий запроса: правила + **категоризатор Jev** (закрытые списки: сценарий, категория, задача, роль, отрасль).
6. План поиска по сценарию: товар / аналог и импортозамещение / комплект для роли или рабочего места / задача своими словами /
   список‑спецификация / продление / вопрос / сравнение / слишком общий запрос / товара нет в каталоге.
7. Гибридный отбор кандидатов (BM25 по полям + символьные n‑граммы + локальные эмбеддинги) и жёсткие фильтры с лестницей ослабления.
8. Склейка SKU в карточку продукта с выбором подходящего варианта лицензии (диапазон количества, срок, новая/продление).
9. Jev‑реранк верхнего окна.
10. Бизнес‑ранжирование: релевантность задаёт «полосы», внутри полосы работают популярность, маржа и персональный контекст.
11. Персонализация: сегмент (малый бизнес/enterprise/гос/образование), история клиента (что куплено, когда истекает), категория, сессия.
12. Ответ: карточки, «понято так», исправления, примечания, фасеты, связанные запросы, аналоги, комплект, ответ на вопрос, трасса, стоимость.
13. Журнал: поиск и события (клик, корзина, заказ, уход) → аналитика и выводы агента для пяти ролей.

Отдельно: подсказки (автодополнение с опечатками/раскладкой, связанные запросы), **база знаний о мире ПО, не зависящая от каталога**
(чтобы узнавать спрос на то, чего в каталоге нет, и предлагать аналоги), сравнение «наивный поиск против умного» на журнале запросов.

## 4. Жёсткие правила для всех

1. Пишем **только** внутри `/home/bb/kuznitsa-softline` и только в своей зоне файлов (указана в личном задании).
2. **Запрещено** менять что‑либо в `/opt/aixenix-search`, `/var/lib/aixenix-search`, `/etc/aixenix-search`,
   `/home/bb/esp32/*`, в systemd, Docker, Caddy и любых работающих службах. Боевой поиск спецодежды должен остаться как был.
   `sudo` не использовать. Службы не запускать и не перезапускать. Порты наружу не открывать.
3. Справочные материалы в `/home/bb/kuznitsa-softline-ref` — только чтение.
4. Секреты (ключи, токены, пароли) не читать, не печатать и не записывать в файлы проекта.
5. Сайт store.softline.ru не обходить роботом: разведка уже сделана. Каталог Softline целиком не копировать;
   mock‑данные — синтетические, по реальным названиям продуктов (названия продуктов — общеизвестные факты).
6. Факты о продуктах (реестр российского ПО, сертификаты ФСТЭК/ФСБ, совместимость, уход вендора с рынка) указывать только
   при уверенности; иначе оставлять пустым или ставить `confidence: low`. Номера реестровых записей и сертификатов не выдумывать.
7. Данные спецодежды, названия и бренды того проекта в новый проект не переносить.
8. `git commit` не делать — фиксирует архитектор. Файлы других участников не править; замечания к ним — в свой каталог.
9. Язык документов и данных — русский; идентификаторы — `snake_case` латиницей.
10. В конце работы — короткий отчёт: что сделано, список файлов, что не успели, какие есть сомнения.
